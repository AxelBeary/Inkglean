## 一、背景与目标

用户原话：「要安全点，我怕被请去喝茶。如果之后真要国内部署也方便？」

核心认知：内容风险的本质是「平台上违法内容（色情/政治敏感/侵权）有没有管」。方案 = **标准版协议（文案）+ 内容安全机制（功能）**，后者才是防喝茶的硬功夫：有举报、有处理、有记录。

## 三、方案设计

### A. 隐私政策（标准版，静态页 `/privacy`）

- 数据清单：QQ 号、联系方式（contact_qq）、订单需求/备注、作品图/完稿、浏览行为（埋点三态可关）、Passkey 公钥
- 内容：收集目的、**存储位置（海外，可随部署调整）**、保留期限（埋点 180 天 TTL）、用户权利（查询/更正/删除/导出——**实现路径：联系管理员处理**，2026-08-11 拍板 A；画师自助导出/注销后补 P 系列）、联系方式、更新日期
- 引用法规：PIPL、网络安全法、数据安全法
- 页脚链接（客户端 Landing + 画师主页）

### B. 服务条款 + 画师协议（静态页 `/terms`）

- 画师内容责任（对自己上传内容负责）+ 平台处理权（下架/封禁）
- 违规阶梯：警告 → 内容下架 → 封禁
- 内容红线清单（违法内容）
- **实名预留条款**：「必要时按法规要求实名」
- 免责声明：平台是工具，交易由画师与客户自行协商；平台不介入交易纠纷
- 未成年人声明
- 同意时机：邀请码入驻勾选「已阅读并同意」+ 客户首单勾选（简版）

### C. 内容安全机制（功能，核心）

| 机制 | 需求 |
|------|------|
| **举报入口** | 页脚底部统一入口 → 举报表单（类型：画师主页/作品/留言/其他 + 描述 + 可选联系方式）→ 入管理员待处理列表；匿名可举报 |
| **敏感词提示** | 内置基础敏感词库，画师发布作品/留言/主页内容命中时弹提示（不硬拦，先发后审）；管理员可维护词库（后置，可 P2） |
| **内容级下架** | 管理员对具体内容下架（作品/留言/主页），客户端立即不展示 |
| **封禁独立态** | `artists.is_banned`（独立字段，不动 status 三态）：封禁=主页强制下架 + 登录拒绝 + 后台标记；管理员可解封 |
| **处理留痕** | 新表 `admin_actions`（admin_id、action、target_type、target_id、reason、created_at）：下架/封禁/举报处理全部留痕，可查 |

### D. 国内部署预留

- 部署文档加「国内部署 checklist」：ICP 备案 + 公安备案 + 域名实名流程
- 隐私政策存储位置文案兼容两种部署
- 实名制条款预留（见 B）

## 四、后端

- 迁移 v59：`admin_actions` 表 + `artists.is_banned` 列
- API：
  - `POST /api/public/reports`（公开+限流：举报提交）
  - `GET /api/admin/reports`（列表：待处理/已处理）
  - `POST /api/admin/reports/:id/resolve`（标记处理，写留痕）
  - `POST /api/admin/content/:type/:id/remove`（内容下架，写留痕）
  - `POST /api/admin/artists/:id/ban` / `unban`（封禁/解封，写留痕）
- 登录拦截：`is_banned` 画师登录拒绝（错误码 BANNED，前端可读文案）
- 客户端过滤：`is_banned` 画师不出现在目录/主页
