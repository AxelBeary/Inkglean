## 一、问题定义（来源对话的核心诊断）

1. **现有表达只对口局内人**：README 第一屏 = 项目名 + git 链接 + 技术栈表。对「已经是用户、懂 git 的画师」没问题，但对 99% 不懂 git/不知 Eagle 的画师和投资人是劝退页（用户原话复盘："我作为一个用 git 的人，都有不想打开的冲动"）。
2. **缺一句话定位**：没有「类 Eagle 的、为画师提供本地部署的接稿平台」级别的电梯陈述；且 Eagle 类比对 99% 画师无效，需要更普遍的锚点。
3. **缺应用商店式详情页**：未来上架（web 详情页 / 桌面端分发）必备物料不存在。
4. **主次排布缺客观依据**：界面「好看 = 主次 + 节奏感，不是装饰」；目前默认布局的主次排序靠内部拍板，没有来自画师的一手证据。
5. **表达习惯缺审查机制**：每次对外输出需要一道「外行 10 秒能懂吗」的自查。

## 二、工作项清单（完整待办）

### A. 一句话定位体系（✅ 2026-09-12 用户拍板定稿）

三层话术，按受众取用，**禁止拿 Eagle 类比当地毯**（只对懂行者用）：

| 受众 | 锚点 | 定稿话术 |
|------|------|------|
| 普通画师（99%） | QQ 接单 / Excel 记账 / 备忘录排期（他们已经在用、且痛的东西） | 「把 QQ 接单、Excel 记账、备忘录排期，换成一个网站——客户自助下单查单，你只管画。」 |
| 懂行画师 / 圈内人 | Eagle 类比 | 「类 Eagle 的、为画师提供本地部署的接稿管理平台。」 |
| 投资人 / 非画师 | 数据主权 + 独有机制 | 「开源自托管，数据在画师自己手里；**正在开发的**桌面端能自动识别你正在画哪张稿，帮你记工时。」 |

- [x] 用户逐句拍板三层话术最终口径（2026-09-12）

**拍板记录（防后人把定稿当成未审文本重改）**：

1. 第一层「一个网站」措辞**经主代理提出、用户维持原样**：主代理当时的意见是「网站」会让人觉得东西轻飘飘、且与第三层「数据在自己手里」存在观感矛盾，建议改为「装在自己电脑上的接单管家」；**用户拍板不抽**，判定该矛盾不是问题。→ 不得以后以“口径不一致”为由自行改动此句。
2. 第三层加「正在开发的」限定：桌面端至今未发布（版本 0.1.0、无 `desktop-v*` tag、发布卡在四项只有用户能做的后台事），对外不得把未发布能力写成现在时。
   → **重评与改口径条件**：桌面端首次发布后，本句可去掉「正在开发的」；去掉即得重新拍板。
3. 第二层本次未逐句审，沿用草案原文。
4. 未采纳项归档：「全网唯一有的东西」（竞品结论束于 8/24 七轮调研，但对外锐度措辞需用户另行点头）、「我们碰不到」（未写入定稿）。
