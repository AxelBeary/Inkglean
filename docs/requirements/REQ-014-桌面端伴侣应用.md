## 产品定位

**一句话**：画师的本地工作台——管稿子、记账、出图，联网后和拾绘平台无缝对接。

**核心原则**：
- 本地优先：所有核心功能不依赖网络
- 登录是"升级"不是"门槛"
- 平台是加分项，不是前提

---

## 模式设计（2026-08-10 用户拍板）

> 用户原话："做本地和云端功能分离。要么本地 要么全云。我们的软件在本地状态和云端状态都能帮助跟踪 帮助下单等。需要联网的功能直接隐藏。"

- **双模式完全分离**：本地模式与云端模式是两个独立完整的世界。两种状态都能独立完成委托跟踪、接单管理；**本地记账与平台订单不做任何关联/合并**（原开放问题 1 据此关闭）
- **联网功能离线隐藏**：断网或未登录时，所有需要联网的功能直接隐藏，不出现禁用态/报错态
- **本地模式完全脱网**：本地模式下不发起任何网络请求，含更新检查在内（连更新都不给）；更新检查仅在云端模式（已登录 + 联网）执行，另提供设置项可关闭自动检查。（824 口径澄清，第三方接入研判部分拍板③：脱网＝不碰公网；对本机本地应用如 Eagle 的 localhost 调用不算公网请求，允许）
- **导出边界**：仅本地创建的数据可导出（Excel / 数据包）；平台数据不进入桌面端导出（已有 F5 缓存图不导出条款，本条为总原则）。（824 口径澄清，第三方接入研判部分拍板④：画师自有第三方账号如同步回来的爱发电订单视同本地数据，可导出）
- **传播影响（已解决）**：本决策曾与 F6/F7"首次登录档案对比"冲突——2026-08-10 用户进一步拍板：在线/离线完全独立，F7 整体砍掉，登录后平台为准

## 功能清单

### F1 本地文件管理

- 按委托/项目归档本地文件（CSP、PSD、PNG 等）
- 快速打开工程文件（调起系统关联程序）
- 文件与委托记录关联（一个委托下挂多个文件）
- **文件保持原样在磁盘**：应用只记录路径，不复制、不搬迁、不封装
- **文件丢失提醒**：应用启动时（或定时）校验所有关联路径，文件不存在时提示画师"文件找不到了，是被移动了还是删了？"，画师可重新指路或忽略
- 工程文件可被 Everything 等系统工具直接搜索（因为就是普通文件）
- 工程文件可被其他软件（CSP、PS、SAI）直接打开修改（应用不锁定、不占用）

#### F1a 工程文件模板

- **用途**：创建订单时自动准备工程文件，省去画师每次手动建文件的步骤
- **模板存放**：`我的文档\拾绘\templates\`，画师上传的原始文件（CSP/PSD/SAI 等）
- **绑定关系**：
  - 全局默认模板（所有未绑定档位的订单用这个）
  - 档位级覆盖（"头像"绑 A 模板，"全身"绑 B 模板）
  - **一个档位只绑一个文件**（用户确认"画师不太会闲着没事左右横跳"）
- **创建订单时**：
  - 有模板 → 复制副本到委托文件夹，命名「客户名-档位名.扩展名」（如「张三-头像.csp」）
  - 没模板 → 只建文件夹，不建文件
  - 模板本身永远不动，每个订单拿到的是副本（"母版"和"复印件"的关系）
- **模板更换**：画师随时重新上传覆盖，已创建的订单文件不受影响
- **创建后行为**：只创建不自动打开。订单详情页关联文件旁显示蓝字链接（如「在 CSP 中打开」），点击调起系统关联程序。文件不存在时链接灰掉 + 提示
- **平台订单**：登录后同步下来的平台订单同样享受自动创建（订单不分来源）
- **格式兼容**：不需要管。画师在 CSP 里画完想换 PS 修图，自己"导出→PSD→PS 打开"即可，全程普通文件操作，与应用无关。一个委托文件夹里可以同时放 .csp、.psd、.png 多个文件
- ❌ 不做空白画布快捷创建（CSP 无公开命令行 API，伪需求）

### F2 本地委托记账

- 记录：客户名、委托类型、价格、截稿日、状态
- 纯本地，不需要网络
- 状态流转（草稿 → 进行中 → 已交付 → 已收款）由画师手动标记
- **导出**：支持导出为 Excel（.xlsx），导出范围 = 当前列表筛选结果
- 结构化数据存 SQLite，路径透明（`我的文档\拾绘\data.db`）
- 不允许应用内直接编辑原始数据库；"看数据"通过导出 Excel 覆盖

### F3 约稿条生成

- **双端同做（2026-08-10 用户拍板）**：用户原话"这个算是小功能，我网页版也想做"——约稿条为 Web/桌面共享功能，实现为共享 Vue 组件一次开发两端复用；桌面端独有的是"本地拖入图片"输入路径

- **用途**：画师发社交平台（微博/小红书/米画师）招揽客户
- **排版模式**：模板填空（A 档）。预设模板，画师只做换图、改文字、选配色。不支持自由拖拽布局
- **输出**：PNG 图片 + 纯文字版（复制粘贴用）
- **模板数量**：2~3 套长条（竖版）+ 1 套横版，区别在排版风格（如简约白底 / 深色质感 / 可爱贴纸风），元素区域相同，视觉不同
- 用户原话（2026-08-02）："真有设计需要他们也都会去别的软件去做对吧，他们自己就是搞艺术"

#### F3 模板结构（五个区域）

```
┌──────────────────────────┐
│  [头像]  画师昵称         │ ← ① 头部区
│  一句话简介 / 风格标签     │
├──────────────────────────┤
│  [头像例图]  头像 ¥100   │
│  [半身例图]  半身 ¥200   │ ← ② 档位区（例图+价格一体）
│  [全身例图]  全身 ¥350   │
├──────────────────────────┤
│  [作品A]  [作品B]        │
│  [作品C]  [作品D]        │ ← ③ 额外作品展示区
├──────────────────────────┤
│  · 修改 3 次以内          │
│  · 工期 2~4 周            │ ← ④ 约稿规则区
│  · 先款后稿               │
├──────────────────────────┤
│  QQ: 123456  微博 @xxx   │ ← ⑤ 联系尾部区
│  [二维码]                 │
└──────────────────────────┘
```

- **① 头部区**：头像 + 昵称 + 简介/标签（来自 F6 画师档案）
- **② 档位区**：每个档位一行，左边例图右边价格。客户一眼看到"这个价位长这样"
  - 价格来源：登录后从平台档位拉取（可编辑），免登录纯手填
  - 例图来源：登录后从平台档位 `focus_image` 拉取，免登录画师手动拖入
- **③ 额外作品展示区**：和档位无关的"我就是想秀一下"的图。最多 6 张（2 列 × 3 行），可少放
  - 来源：登录后从平台代表作选 / 本地拖入均可
- **④ 约稿规则区**：纯文字，画师自由填写（修改次数、工期、付款方式、不接类型等）
- **⑤ 联系尾部区**：联系方式 + 可选二维码

### F4 委托小票/回执

- **双端同做（2026-08-10 用户拍板）**：同 F3，Web/桌面共享组件（用户原话"如3"）

- **用途**：发给客户确认委托详情（"你约了什么、多少钱、什么时候交"）
- **输入**：从 F2 记账数据自动填充
- **输出**：PNG 图片 + 纯文字版
- ❌ 不做 PDF（"很多单主连 PDF 是啥都不知道"——用户原话）
- **签名/印章**：
  - 主路径：上传签名图片（PNG 透明底），全局设置一次，所有小票复用
  - 辅助路径：应用内手绘签名板（优先级低于上传，可延后）
  - 不做每张小票单独选签名

### F5 平台图片缓存（登录后）

- 单个委托最多 20 张图（与平台 `REFERENCES_LIMIT` 对齐）
- 上传：拖入，逻辑与网页端一致
- 下载/缓存：首次拉取后存本地，下次打开免流量
- 不做文件同步（只缓存图片，不同步 CSP/PSD 等工程文件）
- 平台缓存图片**不纳入导出打包**（来源是平台，登录后可重新拉取）

### F6 画师档案（本地）

- 字段：昵称、头像、简介、风格标签
- 约稿条（F3）和小票（F4）复用此档案
- 免登录阶段：画师手动创建/编辑
- 登录后：平台为准（F7 对比机制已砍掉，见下）

### F7 首次登录档案对比（❌ 已砍掉，2026-08-10）

> 用户拍板："我们在线的和离线的完全独立，彻底避免类似问题"——在线/离线完全独立，混合对比机制整体移除，彻底避免本地/云端数据混淆类问题。登录后画师档案直接以平台为准（本地档案仅作未登录态使用）。

- 触发条件：本地已有档案 + 平台也有档案
- 交互：左右对比界面，逐项（昵称/头像/简介/标签）让画师选哪边赢，或手动改
- 确认后：平台为 source of truth，本地变为缓存
- 本地无档案 + 平台有：直接用平台数据
- 本地有 + 平台无（新注册）：本地推上去

### F8 画画时间统计（2026-08-24 用户拍板立项）

- **用途**：画师想知道「这张单我到底画了多久」——为报价、估价、复盘提供依据，摸鱼可视化
- **四种计时来源（组合，不互斥）**：
  1. **手动计时**：委托详情页「开始画/暂停/结束」按钮，画师自觉打卡（兜底通道）
  2. **自动识别正在画哪个文件**：后台常驻监听前台窗口，自动识别 CSP（.clip）/PS（.psd）/SAI 等绘图软件当前打开的文件名，按「文件名 ↔ 委托文件夹」匹配归属自动计时；跨软件切换不断档（CSP 画完换 PS 修图都算这张单）
  3. **自动识别 AFK**：检测键盘/鼠标输入空闲，超时（默认 5 分钟，可调）自动暂停计时——离开工位不计工时
  4. **自动识别摸鱼时间**：前台窗口分类（绘图软件 = 工作；浏览器/游戏/视频 = 摸鱼；文档/通讯 = 中立），摸鱼时段单独统计，出「实际画画 vs 摸鱼」日/月对比图
- **输出**：订单详情显示「已画 14.5 小时」；排期看板与收入页可切「按工时」视图；导出 Excel 含工时列
- **边界**：计时数据仅存本地 SQLite，属可导出范围、不传平台（双模式分离纪律）；首发只承诺识别画师主力软件（CSP/PS/SAI），其余软件识别按需求后补
- **工程备注**：自动识别需少量 Windows 原生能力（窗口标题枚举 + 输入空闲检测），封装在 desktop-bridge 逃生层内；本地模式完全脱网不受影响

## 数据迁移与备份

### 导出

- **触发方式**：纯手动。设置页"导出全部数据"按钮，不主动提醒
- **导出内容**：
  - 数据包（zip，几 MB）：SQLite 数据库 + 签名图片 + 本地设置
  - 文件清单（manifest.json）：所有关联工程文件的路径、大小、所属委托
- **不包含**：平台缓存图片（登录重新拉）、工程文件本体（画师自行搬运）
- **云备份提示**：导出目录选择器下方显示提示文字："💡 将导出目录设为坚果云 / OneDrive 同步文件夹，可实现自动云备份"。不做网盘集成

### 导入

- **策略**：替换。不做合并，不做手动逐条核对
- **冲突处理**：导入前检测本地是否已有数据。若有，弹强提醒：
  > ⚠️ 你本地已有 N 条记账记录。导入将替换它们。
  > 我们会先把当前数据自动备份为「拾绘备份-替换前-{日期}.zip」，万一后悔可以恢复。
  > [取消] [确认替换]
- 确认后：自动备份当前数据 → 导入新数据
- **工程文件关联恢复**：导入数据包后，根据 manifest.json 提示"检测到 N 个委托文件夹尚未关联，请指定位置"，画师手动指向文件夹路径

### 设计原则

- 数据（记账、档案、设置）我们管——一键导出导入
- 文件（CSP、PSD）画师自己搬——12GB 的东西用画师自己的方式搬最快
- 应用只记路径，不拥有文件

## 技术选型（2026-08-10 用户拍板：Tauri 2）

> **结论**：Tauri 2（Rust 壳 + 系统 WebView）。研判人：一号；拍板人：用户（2026-08-10，用户原话"很好 选这个作为框架"）。
> 候选对比：Tauri 2 / Electron / PWA / Vercel Native SDK / Wails / Flutter。

### 选型理由

1. **功能全覆盖，自定义 Rust 代码趋近于零**（团队零 Rust 储备，此为前提条件）：
   - 文件读写/存在性校验/复制模板副本 → `tauri-plugin-fs`
   - 调起系统关联程序（"在 CSP 中打开"）→ `tauri-plugin-shell`
   - 文件对话框/保存位置 → `tauri-plugin-dialog`；拖入文件 → 内置 drag & drop（拿真实路径，非 Blob 副本）
   - 本地 SQLite（`我的文档\拾绘\data.db`）→ `tauri-plugin-sql`
   - 自动更新 → `tauri-plugin-updater`
   - Excel 导出 / 约稿条 PNG → 纯 JS 在 WebView 内跑（xlsx + canvas），与浏览器端同写法
2. **分发转化**：官网下载安装包 5~20MB（Electron 空壳 100MB+），画师下载门槛低
3. **机器画像**：画师电脑常驻 CSP/PS，Tauri 低内存占用是产品级体验差异
4. **Windows 渲染一致**：WebView2 即 Chromium 内核，与网页端目标环境一致（目标用户 Windows 为主）
5. **安全模型**：capabilities 沙箱配置声明放行目录（用户自选委托目录 + `我的文档\拾绘\`），纯配置不写 Rust
6. **与 F1 纪律天然契合**：操作真实磁盘文件路径，无 asar 类封装，文件可被 Everything 搜索、被 CSP 直接打开

### 逃生门设计（实施时强制）

前端所有原生调用收口到 **`desktop-bridge` 适配层**（文件对话框/调起程序/SQLite/保存文件等，约十几个函数）。壳层换技术栈时 UI 零改动，只重写适配层——把选型降级为可逆决策。

### 改选 Electron 的触发条件（备案）

- 出现插件覆盖不了的原生需求，且 Rust 学习成本不可接受
- 决定做"桌面端内嵌本地 server 的完全离线模式"（Electron 的 Node 环境可直接复用 server 侧 better-sqlite3 / DB 迁移模式）

### 平台与更新（2026-08-10 用户拍板）

- **平台范围：Windows 单平台首发**。画师主力平台 + WebView2 零渲染差异；macOS 留二期（WebKit 内核，届时需样式适配验证）
- **更新方式：自托管服务器静默更新（tauri-plugin-updater）**。用户 2026-08-10 拍板（原"手动下载"拍板被覆盖）：包体仅 5~20MB，全量更新下载几秒即完，直接走自己服务器
  - 更新源：现有服务器静态托管（Caddy 已提供 HTTPS，满足 updater 强制 TLS 要求）：版本清单 JSON + `*.nsis.zip` 更新包 + 签名文件
  - 静默语义：后台静默下载 + 验签，下载完成后择机提示重启生效（Windows 上应用重启不可避免，属正常交互）
  - 签名：Ed25519 密钥对，私钥只在发布/CI 环节，公钥内置于应用配置
  - **增量更新不做（备案）**：Tauri 官方 updater 无内置 delta 机制（已对照官方文档核实）；全量包本就 5~20MB，增量省的下载量不抵差分流水线/版本链/回退逻辑的工程成本。重评条件：未来包体显著膨胀（如内嵌模板资源超 50MB）

### 五、安全口径三条（开工前强制基线——回答「桌面端是否威胁服务器」）

**研判结论**：桌面端本身不新增服务器攻击面（复用既有 REST API、无专用特权端点、不开监听端口）；真实风险集中在凭证生命周期放大与两处防护参数变更，三条口径钉死后收敛回网页端同量级。

1. **90 天凭证——方案 A 服务器记账式会话**：登录在服务器记一笔账（设备/到期/最后活跃），踢人/到期/顺延=撕账改账；824 拍板的设备清单+单台踢出据此做干净，杜绝「顺延后旧凭证仍存活」暗坑。**登录凭证强制存 Windows 系统保险箱（凭据保管柜/DPAPI），不存明文文件**——防硬盘被拷/换账户翻查；边界诚实备注：同账户实时木马仍可偷，但门槛从「明文随时可抄」提高到「必须实时潜伏」
2. **免验证通道——只免登录类接口，不整站放行**：验证质询主要出现在未登录环节，登录后的会话请求本就少触发质询；开口最小化。桌面端「身份标签」仅用于分流与统计，**落档写死：标签可伪造、不是安全关卡**；真正防线=既有应用层三道门（登录限流 10次/5分、错5次锁15分、TOTP 重放防护）+ AOP 源站认证（TLS 层，不动）
3. **更新通道防投毒三件套**：①更新签名私钥永不进服务器（发布流水线签名，服务器只托管成品）；②客户端验签失败=拒装，静默安装不得绕过；③服务器保留前几版更新包，坏版可回滚。另澄清：SignPath 签名（防 SmartScreen 误报）与更新签名（防掉包）是两回事，各防各的，都要做。风险链备注：更新通道是「服务器失陷→毒包→全体画师电脑」的最大爆炸半径路径，故为强制基线

### 六、仓库与开发形态拍板

- **同仓开发**：桌面端于现有仓库加 `desktop/` 目录（与 web/server 平级），不单独开仓库、不单独开开发 profile（AI 助手按目录领地派活即可）；共享 Vue 组件与 API 对接类型同仓复用，F3/F4/F12 双端同做与 F9/F11/F12 回流网页端均依赖此形态
- **拆分重评条件**：桌面端膨胀为与平台完全分家的独立产品时，再从共享组件处切开拆仓
