## 三、交互流程与判定（照代码实况）

```
交付成功
  ├─ 来源①订单详情页：DeliverDialog @delivered → onOrderUpdated(updated)
  └─ 来源②排期看板：  DeliverDialog @delivered → onDeliveredFromBoard()（现签名不收参数，改造后收 updated）
        ↓
      判定：updated.deliverables 里是否有「可发布为作品的交付图」
            （沿用 PUBLISH_IMAGE_EXTS = .jpg/.jpeg/.png/.webp/.gif 单一事实源，与弹窗置灰逻辑同源）
        ↓ 否（纯 zip/psd/无文件交付）→ 不弹，直接结束
        ↓ 是
      查询持久化：用户全局「不再提示」？该订单已弹过？→ 命中则不弹
        ↓ 否
      弹卡（浮层，展示 已交付 · 订单号 + 客户 + 缩略图N张 + 三个动作 + 「知道了」/「不再提示」）
        ├─ 发布为作品 → 打开既有 PublishShareDialogs.openPublish()（默认已勾选图片，逻辑零改动）
        ├─ 分享完稿   → 打开 PublishShareDialogs.openShare()（自带分享文案模板 shareTemplate 与占位符）
        ├─ 打开图片水印 → 路由跳 /tools/watermark?source=deliverable&order=<id>（预选本单完稿图）
        ├─ 知道了     → 关卡；该订单标记已弹，不再对该订单重复弹
        └─ 不再提示   → 关卡 + 全局永久静默（保留订单详情里的手动入口不动）
```

**三条硬规矩**

1. **一图一单只弹一次**：同一订单二次进入/重复交付不再弹；不做「今天晚点再说」这类延期态（复杂度不值）。
2. **不打断主流程**：交付失败、乐观锁 409（`@conflict`）一律不弹；卡不阻塞队列刷新。
3. **不新增网络请求**：卡片要的数据全部来自交付接口已回传的 `DeliverResult`，不额外拉单；缩略图沿用详情页已有的签名 URL 刷新链路。

**持久化**：`localStorage`（走 `utils/storage` 的 `safeGetItem/safeSetItem` 封装，存储被禁时静默降级不弹错），键名 `inkglean_delivered_guide_v1`，形状 `{ neverAsk: boolean, shownOrderIds: number[] }`，`shownOrderIds` 截断保留最近 200 条防无限膨胀。与站内既有键口径一致（如 `inkglean_tour_seen_v1`）。

## 四、shared 哑组件契约草案（`shared/src/components/DeliveredGuideCard.vue`）

哑组件纪律（`shared/README.md` 契约第 2、4 条 + 824 定稿口径）：**不发请求、不读存储、文案零硬编码、颜色圆角只用宿主注入的 token**。

```ts
// props（数据进）
t: (key: string, params?: Record<string, unknown>) => string  // 必填，宿主注入
locale?: string                                                // 默认 'zh-CN'
order: { id: number; orderNo: string; clientName: string | null }
images: Array<{ id: number; name: string; url: string }>       // 宿主已按扩展名过滤好
// emits（事件出）
'publish'    // 无参；宿主调 PublishShareDialogs.openPublish()（标题「发布为作品」）
'share'      // 无参；宿主调 openShare()（标题「分享完稿」，发社交平台 + 自带文案模板）
'watermark'  // payload: { orderId }；宿主路由跳图片水印工具并预选本单完稿图
'dismiss'    // payload: { forever: boolean }（false=知道了 / true=不再提示）
'open'      // 卡片首次展示（供宿主做「该单已弹过」记账，不内嵌持久化）
```

- **不 expose 任何方法**，不发 canvas/blob，不需要 `export-png`/`copy-text`/`notify` 三类既有事件（本卡无导出无复制；toast 归宿主）。
- **token 超纲禁令**：只消费 README 已登记的 15 个注入变量（`--paper2/--card/--ink/--ink2/--ink3/--line/--line2/--hq/--zs/--white/--r-s/--r-m/--r-paper/--font-scale/--dur-fast`）。要新 token → 先走视觉 token 事实源批（G6/泥金那条红灯不在此扯皮）。
- **桌面端 token 注入层**仍是 README 记的开放项：桌面端宿主若同批接入，需自备注入，否则卡片在桌面端会裸色 → 建议 C 方案里桌面端只登记"待桌面施工批接"，**不强求同批点亮桌面端**。

## 十一、话术口径约定（施工批照此执行，不得自造词）

本轮用户点名“话术口径和现有不一致”后，定下三条硬规则 + 一把机器锁：

1. **动作名 = 站内既有词条原文**。卡片上每个可点东西的名字，必须能在 `locales` 里找到同一个词（`发布为作品` / `分享完稿` / `图片水印` / `不再提示` / `知道了`）；新页面入口不得给旧功能起别名。
2. **术语分域不串位**：「追踪链接」只属于**客户侧查单**；「分享完稿」属于**画师发社交平台**；「交付图」是发布语境用词、「完稿图」是水印工具页用词（沿用各自现状，不在引导卡里强行统一）。
3. **新机制先查存量**：写“这需要新机制”之前，先 grep `locales` 与相关组件（本轮就是没查 `shareTemplate` 导致误判，已记录修正）。

**已上的机器锁**（取证脚本 `temp/f12-proto-verify.mjs`，不入库，施工批应把这 8 条话术断言以单测形式落进仓库）：

- 判定链断言一律绑 `data-branch` 键而非文字——以后改文案不会把测试带沟里。
