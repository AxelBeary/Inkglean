## 一、判定要点（结论级）

1. **两份 PR 与一条警报的分工**：警报 #83（rustls，medium，`desktop/src-tauri/Cargo.lock`）与 PR #16 同源，属"范围内可取已修版"，先合即自动关单；
   PR #15（npm 分组 32 项 minor/patch）不能直接合——它到手就是红的，且含两处越界改动（见第 3、4 条）。
2. **web 红的真凶是 vue-tsc 3.3.12，不是 element-plus**（两条独立侦察结论冲突，以推翻式复验定案）：
   - element-plus 2.14.3 与 2.14.7 的 `es/components/message/index.d.ts` **逐字节相同**，`el-upload` 的 `onExceed` 契约未变；
     `src/message.d.ts` 确有差异但全在 `customClass` 类型拓宽与联合字面量顺序，与 `.value` 无关。
   - 该 PR 未动 vue / @vue/compiler-dom / @vue/shared / typescript → 排除法只剩 EP 与 vue-tsc 两个变量。
   - @vue/language-core 3.3.10/3.3.11 无 `codegen/template/bindingReferences.js`、无 `dotValue` 符号、无 `__VLS_withDotValue` helper；3.3.12 三者齐备（发版说明条目 "fix: support calling template bindings without .value"，源头重构 PR #6184）。
   - 机理：模板内联箭头函数/闭包内对 **import 绑定**做属性或元素访问 → 被登记为 narrowing 位 → 第二趟 codegen 在该绑定后裸插 `.value`；顶层断言收窄带不进嵌套函数（import 绑定不享受 const 的闭包保留规则），故报 TS2339。
   - 上游同型 issue vuejs/language-tools #6237、修复 PR #6238 **至 2026-10-13 仍 open 未合并**；3.3.13 与 3.3.12 的 codegen 文件哈希全同 → 升 3.3.13 无用，"等上游"不得写进排期。
   - 结论：改写法根治（抽具名 `function`），不动依赖版本、不用 `@ts-ignore`/`any`。全仓模板区按四条正交口径重扫（import 绑定 681 个、模板区属性/元素访问、`let/var` 绑定、全部含 `=>` 的模板行 49 行逐行判读），
     **真雷仅 1 处**（`ManualOrderLeft.vue:45`，即 CI 报错点），**近失点 1 处**（`AdminDashboard.vue:52`，同通道但位于模板顶层故侥幸不报），两处本批一并改掉。
3. **桌面端 7 个 Tauri JS 包属"不可单边跳"的耦合项**：官方口径（https://v2.tauri.app/develop/updating-dependencies/ ）要求核心 `@tauri-apps/api` 与 `tauri` crate **同 minor**、插件 npm 与 crate **精确同号**；
   该比对由 tauri CLI 在 `build/dev/info` 执行，而本仓 CI desktop job 只跑 `cargo check`、`npm run build`（vue-tsc+vite）——**CI 四 job 全绿不等于发版流水线（`desktop-release.yml` 的 `npx tauri build --bundles nsis`）不红**。
   合入前桌面端 5 个插件 JS↔crate 逐一对齐，#15 单独合入即破口，故本批把 Rust 侧配到同号（6 条 `cargo update --precise`，先核心后插件，禁裸 `cargo update` 防越过 npm 同号）。
4. **桌面端 `typescript` 从 ~5.6.2 被静默改写成 ~5.9.3 判定为不该随本批走**：该端 `vue-tsc` 仍 `^2.1.10`（锁内 2.2.12），vue-tsc 2.2.x 的 peer 只声明 `typescript >=5.0.0`、官方无 TS 5.9 支持矩阵；
   CI 恰好绿只证明"这一次能编过"，不背书类型检查语义漂移（2.1.x 遇 TS 5.7.2 曾硬崩，language-tools #5018）。故退回 5.6.2，收敛动作转待拍板 U31。
5. **@vue/test-utils 2.4.11→2.5.1 是本批唯一"CI 从未验证过"的面**：web job 在 typecheck 就红，其后 `vitest run` 根本没跑到；shared 无 CI job。
   官方 v2.5.0 带 breaking（弃 class components #2904）+ 三条行为修正（#2890 重复 mount 后根组件重渲染、#2898 unmount 清 emitted 历史、#2927 findComponent().vm 暴露 defineExpose）。
   本仓实测：全仓零 class 组件（`extends Vue|vue-class-component` 0 命中）；引用 test-utils 的 web 测试 93 个文件 + shared 2 个 → **由本地全量 vitest 覆盖后判安全**（见第二节）。
6. **undici 传递树未回归**：jsdom 30.0.1→30.1.2 把对 undici 的要求从 `^8.9.0` 提到 `^8.11.2`，web/server 锁内 undici 仍是**单副本 8.11.2**，与既有 `overrides.undici ^8.10.2` 相容；未新增第二份副本（18 条 undici 警报那轮的坑没重演）。
7. **Playwright 1.62.1→1.64.0（声明 `^1.54.0→^1.64.0`）风险面在浏览器二进制换代而非 JS API**：本仓 e2e 配置无 `webServer`（server 由 `global-setup.ts` spawn）、无 channel、无 `connectOverCDP/waitForTimeout/force` 等敏感用法；
   唯一与 Chromium 实现强绑的是 e8-passkey 的 CDP `WebAuthn.addVirtualAuthenticator`。本机换装 chromium v1248 后 E2E 14 例（含 e8、e9）全绿；`check-locators` 与 `check-test-tamper` 均为纯文本/git 扫描，不随版本报新错。
8. **Rust 侧权限与配置零风险**（独立复验）：13 条 capability 标识（`updater:default`、`sql:default`、`dialog:default`、`opener:default`、`notification:default`、`core:window:allow-*` 等）在目标新版 crate 的 permissions 定义里**全部仍存在**；
   `tauri-utils` 2.10.1 的 Config 新增项全为可选，本仓 `tauri.conf.json` 无键被删/改名，不会因 `deny_unknown_fields` 在运行期抛。
   同时坐实两处**既有**缺口（升级前后口径相同，非本批引入）：`sql:default` 不含 `allow-execute`，而 `bridge/db.ts` 建表写入全走 `db.execute()`；`opener:default` 不含 `allow-open-path`，而 `bridge/index.ts` 在用 `openPath()` → 转待拍板 U32。
9. **updater 装完是否重启应用＝行为未变**：2.13.2 `updater.rs` 实测 `restart_after_install: true` 为默认（源码注释 "default is `true`"）、`install_mode` 默认 `passive` → NSIS 参数仍 `/P` + `/R`，与 2.10.1 的 `["/P","/R"]` 等价，故**未动 `tauri.conf.json`**。
   该结论来自 docs.rs 上 2.13.2 的 `src/config.rs` 与 `src/updater.rs` 源码，非推测。
10. **登记一条已知行为变更（非阻塞）**：tao 0.37 起 `WM_ENDSESSION` 直接退出进程，系统关机/重启时"关闭到托盘"偏好不再被 `CloseRequested` 拦截。真机关机路径才能观察。
11. **机制关闸**：`.github/dependabot.yml` 将 `/desktop` 拆为独立 package-ecosystem 条目并 `ignore` `@tauri-apps/*` 与 `typescript`（主条目另加 `@tauri-apps/*` 作防御性冗余）；
    Rust 侧**不建** version updates 通道——npm-only 通道天然无法成对，漏洞类更新继续走 Security 侧自动 PR（#16 即首例）。不新增第 20 道 audit 门禁，"门禁全绿"仍为十九道口径。
12. **分组 PR 夹带的传递依赖跳 major 已逐条清点并判为可接受**（口径补登：`ignore` 的 semver-major 只挡**声明依赖**，挡不住 grouped PR 里子依赖树的拾升）：
    master↔HEAD 逐 lock 集合差算得 web 20 / shared 11 / server 10 / desktop 3 / root 0（共 44 处），含 commander 10→14、glob 10.5→13、keyv 4.5→5.6、flat-cache 4→6.1、
    file-entry-cache 8→11、js-beautify 1.15→2、editorconfig 1→3、nopt 7→10、lru-cache 10→11、path-scurry 1→2、@vueuse/core 14.3→15、content-disposition 2→3、
    data-urls 7→8、tr46 6→7、w3c-xmlserializer 5→6、html-encoding-sniffer 6→7、@asamuzakjp/* 、abbrev 2→5。
    **会进生产包的只 2 项且已核无害**：`@vueuse/core 15` 仅被 element-plus 内部消费（`rg '@vueuse' web/src` 0 命中、manifest 未声明）；
    `content-disposition 3` 挂在 `@fastify/static@10.1.5` 下，而本仓 Content-Disposition 头全是手写（`server/src/app.ts:420,423`、`features/admin/health.routes.ts:30`、
    `features/artist/tools.routes.ts:272`）且有测试钉住。其余全属 lint/test 工具链内部。登记目的：让下批能区分"历史已评审放行"与"新漏网"。
13. **成对不变量落到声明层**（工单收尾发现，不是可选美化）：桌面端 `@tauri-apps/api` 与五个插件 JS 原本写裸 `^2`/`^2.x`，意味着"JS↔Rust 同号"只由 lockfile 承载——
    人手一条 `npm install` 就能把 JS 单推到 2.13.x/2.9.x，而 `npm ci` 与 CI 都看不出，直到 `tauri build` 才炸（dependabot 关闸挡得住机器人，挡不住人）。
    本批改为**精确版本**（api 2.12.2 / dialog 2.8.1 / notification 2.5.1 / opener 2.7.0 / sql 2.5.0 / updater 2.13.2），与 Cargo.lock 逐条同号——
    这是官方 "keep the exact versions synced" 口径的机械编码。`@tauri-apps/cli`（devDep、独立发版、无 crate 对子）保持 `^2`。
    实跑影响面：`npm install` 后 `desktop/package-lock.json` 仅变 6 行 specifier（`packages[""]` 镜像），**解析版本零变动**，磁盘实装逐条复核仍为同号。
14. **allowScripts 豁免键逐条复验**（本仓既有坑：跳版后新版的安装脚本可能不再被允许而静默改变安装行为）：五份 lock 里全部 `hasInstallScript:true` 条目与 allowScripts 键对表——
    root `esbuild@0.28.2`；web `esbuild@0.25.12` + tsx 内嵌 `esbuild@0.28.2` + `vue-demi@0.14.10`；desktop `esbuild@0.25.12`；server `better-sqlite3@12.11.1` + `esbuild@0.28.1`；shared `esbuild@0.25.12`——全命中；
    master→HEAD 安装脚本集合唯一 delta 是 root 少掉可选 darwin 依赖 `fsevents` → **无失效豁免、无静默降级**。
