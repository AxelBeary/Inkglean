## 一、判定要点（结论级）

1. **GitHub 11 条开放警报的处置分两类**：@fastify/busboy ×1、dompurify ×2 属"范围内可取已修版"，走锁定点刷新；axios ×8 属"高频复发依赖"，判定为**必须整包移除**而非升版。
   计数口径订正：开工时误记为 12 条 / axios ×7（把 #76 一条警报内的两份公告当成两条），收口 gh 实测为 **11 条 = axios ×8（#74~#80、#82）+ busboy ×1（#81）+ dompurify ×2（#72/#73）**。
   依据实测：axios 单周三批共 12 个 GHSA 披露，当中 5 条只在 Node 侧可达，逐条可核：#79 HTTP/2 adapter 绕过 DNS 与代理控制、#78 HTTP/2 ClientHttp2Session 的 error 事件未处理致 DoS、#77 Node http adapter 的 createConnection 原型污染、#75 fromDataURI 解析 ReDoS、#74 fetch adapter 不执行 maxRedirects:0 的 redirect SSRF；而 #82/#80（继承 headers 与 FormData getHeaders 的 header 注入）与 #76（toFormData 选项原型污染）在浏览器侧仍可达；本项目对 axios 的实际用量只有 `params`/`headers`/`timeout`/FormData 四项（`npm ls axios --all` 证明无其他宿主）。
2. **拆 axios 的风险判定为可控**：全部 251 处调用收口在 `web/src/api/modules/http.ts` 一个文件的 5 个 helper 里，无 view/store 直接使用 axios 实例；桌面端与网页两处 blob 下载早已是原生 fetch，两端 HTTP 口径就此统一。
