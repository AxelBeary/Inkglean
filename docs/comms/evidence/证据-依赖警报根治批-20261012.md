## 一、判定要点（结论级）

1. **GitHub 12 条开放警报的处置分两类**：@fastify/busboy ×1、dompurify ×2 属"范围内可取已修版"，走锁定点刷新；axios ×7 属"高频复发依赖"，判定为**必须整包移除**而非升版。
   依据实测：axios 单周三批共 12 个 GHSA 披露，其中 5 个只在 Node 侧可达（HTTP/2 adapter、createConnection、fromDataURI），但 header 注入与 toFormData 原型污染在浏览器侧仍可达；而本项目对 axios 的实际用量只有 `params`/`headers`/`timeout`/FormData 四项（`npm ls axios --all` 证明无其他宿主）。
2. **拆 axios 的风险判定为可控**：全部 251 处调用收口在 `web/src/api/modules/http.ts` 一个文件的 5 个 helper 里，无 view/store 直接使用 axios 实例；桌面端与网页两处 blob 下载早已是原生 fetch，两端 HTTP 口径就此统一。
3. **本地 `npm audit` 比 GitHub 更红**：批前 root 0 / server 5 / web 6 / desktop 4 / shared 4。vue、fastify、sharp、source-map-js、postcss-selector-parser 尚未被 GitHub 扫出（披露晚于上次扫描），故本批按"四端全清零"而非"只清已报"施工，避免下周重跑一轮全量门禁。
4. **锁刷新全程无破坏性跳版**：77 个锁条目变化逐包判档**全为 PATCH**，0 major、0 增删包；better-sqlite3、typescript、vite、vitest、element-plus、@tauri-apps、playwright、tsx、esbuild、chart.js 未被连带顶版。
5. **dompurify 两条 low 警报的实际不可利用**：公告只影响 `IN_PLACE` + 移除节点的 afterSanitize 钩子，本项目用 afterSanitizeAttributes 且非 IN_PLACE；因升级零成本仍照做，不靠争辩关闭警报。
6. **机制补口**：新增 `.github/dependabot.yml`，五目录全覆盖 + 周一批 + minor/patch 合并单 PR + major 不自动出 PR；历批"Dependabot 单目录 PR 覆盖不全只能关掉重做"的返工通道就此结束。
7. **未做的两项**（用户明确只选第三项）：accept.ps1 未增第 20 道 audit 门禁，"门禁全绿"仍为十九道口径。
