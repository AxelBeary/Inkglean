## 2. 链式推进协议（goal 模式；替代原固定时间错开版）

> **机制**：不再预设各批固定触发时刻，改为**接力链**——每批以 `goalEnabled=true`（goal 模式）在独立 Quest 自持推进到完成（门禁绿 + ledger 落盘），完成后**自己 `Get-Date` 取当前时间、用 `manage_scheduled_task` 创建下一批**（`startAt=now+10min`、`timezone=Asia/Shanghai`、`repeat.frequency=none`、`goalEnabled=true`、`message`=下一批链式指令）。下一批必在前批真正完成后才起 → 从机制上根除并发 failed。

**链条全序**（唯一权威定义，各批 Quest 读本节构造下一批）：

| 环 | 批次 | 计划书 | 触发 | 门禁 | 完成后创建 |
|---|---|---|---|---|---|
| 起点 | **W7 落地批** | `定时开工计划书-W7主页文案落地批-20260913.md` | 主会话手动创建 23:38（goal） | web `check:i18n`+`build` | → R3 |
| 2 | **R3 E2E 批** | `定时开工计划书-R3-E2E合规链路批-20260913.md` | W7 完成后 now+10min | 仓库根 `test:e2e` | → R5 |
| 3 | **R5 依赖批** | `定时开工计划书-R5-依赖与CI健康批-20260913.md` | R3 完成后 now+10min | server 三项 | → R4 |
| 链尾 | **R4 收口批** | `定时开工计划书-R4-收口批-20260913.md` | R5 完成后 now+10min | 全量 `accept.ps1` | 无（链条结束）|

**已完成的前两环**（链式改造前用固定时间跑的）：R1（22:01，completed，web 886 例全绿、W1~W6 落地）、R2（22:15 首次 failed→主会话补产出施工图→用户手动重启 completed，**W7 已拍板方案 A**）。故链式从 **W7 落地批**起（落地 R2 拍板的方案 A），接 R3→R5→R4。

**每批链式 message 模板**（Quest 完成后照此创建下一批，替换 `{}`）：
> `【绘约·第二轮·{下一批名}·goal 链式】你是绘约主代理，独立 Quest（goal 模式）触发，无其它上下文。读 docs/comms/{下一批计划书} + 总纲第 2 节链式协议，按计划书施工，goal 模式自持推进到门禁绿 + 写 docs/comms/ledgers/ledger_{下一批}.md。完成后按总纲链式协议创建再下一批 {下下批}（startAt=now+10min、timezone=Asia/Shanghai、repeat.frequency=none、goalEnabled=true、message=用本模板填 {下下批}）；若本批是链尾 R4 则不创建，链条结束。`

**门禁天然串行**：链式保证前批完成 +10min 才起下一批，跑门禁的批（W7 web / R3 E2E / R5 server / R4 全量）**永不并发**，杜绝抢 cache/build；10min 缓冲确保前批 Quest 完全释放资源。

**🔴 断链风险与兜底**（链式固有脆弱点，须知情）：
- **风险**：某环 Quest failed（撞其他项目并发、或施工崩溃）→ **不会创建下一环 → 链断**，后续全不触发。
- **兜底 1**：`goalEnabled=true` 让 Quest 自持多轮续跑，比单次 Quest 抗失败。
- **兜底 2（不可控项）**：本机同时段有 renpy 夜间集群（批 2~6）与麻将项目在跑，链式只保证绘约内部串行，**撞其他项目仍可能 failed**，非绘约编排可消除。
- **兜底 3**：R4 收口前置校验各批 ledger 齐全、缺则停下报你；**若链中途断了，你早上发现“某批之后没动静”就找我，我按 R2 的方式补救（手工补产出或重挂续链）**。
