# 更新通道执行手册（2026-08-25 施工批产出，待后台执行）

> 状态：仓库侧全部就绪（客户端接线 + CI 签名流水线 + Caddy/compose 托管配置），剩余步骤全部在用户手里：密钥、仓库配置、服务器目录。本手册不含任何敏感信息；私钥永不入仓、不进服务器（防投毒口径①）。

## 已经完成（仓库侧，你不用动）

1. **客户端**：tauri-plugin-updater 接线（Rust + JS 双侧，走 desktop-bridge 逃生门）；启动静默检查→后台下载（含验签，验签失败拒装）→询问重启生效
2. **CI 流水线**：`.github/workflows/desktop-release.yml`——推送 `desktop-v*` tag 触发，Windows 构建 NSIS → Ed25519 签名 → 生成 latest.json → 产物发 GitHub Release
3. **托管配置**：Caddyfile 加 `/desktop/*` 只读静态块（latest.json 禁缓存）；compose 给 caddy 容器只读挂载 `./desktop-updates`
4. **NSIS**：installMode=currentUser（画师无需管理员权限装更新）

## ⚠️ 先知道这件事

现在 `desktop/src-tauri/tauri.conf.json` 里的 `pubkey` 是**一次性占位密钥对**的公钥（私钥生成后已当场销毁，只为让配置/构建过关）。**首发前必须换成你的正式密钥对**，否则签出来的包谁也验不过。

## 第一步：生成正式密钥对（本机跑一次）

```
cd desktop
npx tauri signer generate -w <你选的仓库外路径>\shihui-update.key
```

- 会要求设密码（可以设，也可以留空；设了就要记住，密码丢＝更新通道废）
- 产出两个文件：`.key`（私钥）与 `.key.pub`（公钥）
- **私钥保管**：存密码管理器/加密盘，永不入仓、永不进服务器、永不贴进聊天窗口

## 第二步：把公钥换进配置

打开 `.key.pub`，整段（`dW50...` 一行）替换 `tauri.conf.json` 的 `plugins.updater.pubkey` 占位值，提交推送。

## 第三步：GitHub 仓库配置（仓库 Settings）

1. **Secrets**（Settings → Secrets and variables → Actions → New repository secret）：
   - `TAURI_SIGNING_PRIVATE_KEY` = `.key` 文件全文
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` = 密钥密码（没设密码就填空值）
2. **Variables**（同页 Variables 标签 → New repository variable）：
   - `DESKTOP_UPDATE_BASE` = `https://<你的公网域名>/desktop`

## 第四步：服务器建托管目录（公网站点机器）

```
mkdir -p <项目根>/desktop-updates
docker compose restart caddy
```

- 目录先空着没关系（空目录 file_server 返回 404，客户端检查失败静默降级，不影响运行）
- Caddyfile/compose 改动要随下一次部署生效（本机容器重建或服务器 update.sh 时机自定）

## 第五步：首发

1. 桌面端版本号升到要发的版本（`desktop/package.json` 与 `desktop/src-tauri/tauri.conf.json` 的 `version` 同步改）
2. `git tag desktop-v<版本> && git push origin desktop-v<版本>`
3. 等 Actions 跑完，去 Release 页下载四件：`*.exe`（安装包）/ `*.nsis.zip`（更新包）/ `*.nsis.zip.sig`（签名）/ `latest.json`（清单）
4. 把四件放进服务器 `desktop-updates/` 目录
5. 验收：浏览器访问 `https://<域名>/desktop/latest.json` 返回 200 且内容为刚发的版本

## 回滚（坏版应急）

- 目录保留**前 3 版**更新包与签名（投递新版时清理更旧的）
- 回滚＝把旧版的 `latest.json` 重新覆盖回去（旧包还在目录里），客户端下次启动即回旧版

## 发布后验收清单

- [ ] 装机：跑 `*.exe` 正常安装启动
- [ ] 更新：再造一个更高版本走第五步，应用启动后提示「新版本已下载，现在重启完成更新？」，确认后重启变新版
- [ ] 防投毒抽查：手工改坏服务器上的 `.nsis.zip` 一个字节，客户端应静默拒装（不提示、不崩、不装）

## 开放项（不在本手册范围）

- SignPath 代码签名（防 SmartScreen 误报，与更新签名两回事）：申请下来后在 CI 流水线加挂钩位
- 更新检查频率/手动检查入口/托盘提示：桌面端 UI 批再做，现在是启动即查的最小实现
