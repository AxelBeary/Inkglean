## 一、W7 现状核查（施工图第一步，读代码坐实两难）

**触发时先核实以下事实（只读，附文件:行号进施工图）**：
1. **现文案**：`zh-CN.ts:844` `artistHome.hidden` = `'该画师暂未开放主页。如你是店主，请到「设置 → 主页展示」开启「小店展示」。'`（`en.ts:845` 对应）——这是**给自隐身画师的自助指引**语气。
2. **渲染点**：`web/src/views/client/ArtistHome.vue:6-7`（`v-if="artist?.status === 'hidden'"` → `$t('artistHome.hidden')`）——**纯文案渲染，改文案不用动组件**。
3. **同载荷铁证**：`artist-visibility.service.ts:27-30` `isArtistHomeHidden = status==='hidden' ∪ home_takedown_at!=null`；`:15-17` 注释明写**「平台下架在公开端与自助隐身同表现（同一最小载荷），不在响应体里区分原因」**；`types/artist.ts:42-47` `HiddenArtistProfile` 仅 `id/name/subdomain/status`——**客户端结构上无法区分"自隐身"与"被下架"**。

**两难（这就是 W7 必须你拍板的根因）**：
- **改中性「暂时无法访问」**：真·自隐身画师**失去「去设置开启」的自助指引**（他主动关的，但文案不再告诉他怎么开）。
- **不改（保持现状）**：被平台下架的画师看到**错误的自助指引**（"请到设置开启"——但他开了也没用，平台下架画师自助不可解，见 `ledger_P4.md` §9.4 第 3 条），会更困惑挫败。

## 二、施工图要产出的边界选项 + 强推荐（停等你点头）

**呈给你的选项（施工图正文列全，各附受众影响）**：

- **方案 A（兼顾文案，🔵 强推荐）**：主页提示改为中性 + 双指引，例如「该主页当前不可访问。若你是店主且主动关闭了展示，可到「设置 → 主页展示」重新开启；若主页是被平台下架，请在你的后台查看原因与指引。」
  - **三维理由**：① 工程学——纯文案改动（zh-CN.ts:844 + en.ts:845 中英同步），不动组件、不动后端同载荷设计；② 社会学——被下架画师的困惑（"我明明开了怎么还隐藏"）比自隐身画师的困惑更重（后者是自己关的、知道怎么开），兼顾文案给两类人各自出路，且与 R1 的 W4 后台横幅**呼应自洽**（主页提示"可能被下架→去后台看"，后台横幅给原因+指引）；③ 直觉——诚实、不误导任何一方。
  - **代价**：文案略长；且向公开端访客**暗示了"存在平台下架机制"**（若你认为不宜对访客暴露此信息，则选 B）。
- **方案 B（纯中性）**：「该主页暂时无法访问。」——简洁、不暗示下架机制；代价＝自隐身画师也失去自助指引（但他知道自己关的，影响较小）。
- **方案 C（不改）**：保持现状；代价＝被下架画师看到错误的自助指引（开了没用）。**不推荐**（对被下架画师不诚实）。

**推荐结论**：**方案 A**（如你认为不宜对访客暗示下架机制，退而选 B）。**这是推荐、不是已成立的决定**——你点头前 W7 不落地。
