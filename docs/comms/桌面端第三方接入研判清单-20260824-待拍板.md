## 一、研判尺子（判断依据全部来自已拍板口径）

1. **本地优先同构**：本地服务型 API（如 Eagle）与桌面端架构天然同构；在线型 API 一律只能挂在云端模式。
2. **桌面端不开监听端口**（安全口径已拍板）→ Webhook 类推送桌面端无法直接收，只能转「服务器中转 / 轮询 / 文件导入」三条路。
3. **双模式完全分离**：本地模式完全脱网；一切联网接入功能离线时直接隐藏。
4. **F1 纪律**：应用只记文件路径、不拥有文件；接入不得演变为"文件同步/搬迁"。
5. **免费路线偏好**：按条计费、需企业资质的通道天然出局。
6. **导出边界**：仅本地来源数据可导出；平台数据不进导出。
7. **任何接入必须有降级路径**：对方软件没装/没开时退回手动通道，功能不消失、不报错。

## 三、首期建议接入（2 项）

### 首期-1：Eagle（素材管理集成）

- **拍板记录**：824 用户拍板首期双向（归档写入 + 选图读取都做）。
- **接入价值**：素材管理国内事实标准（官方称 24 万+ 付费用户），全生态唯一"高渗透 + 现代 API + 中文生态 + 拥抱 MCP"的交集（调研评分 9.4）。本地服务接口与桌面端本地优先架构同构，**是"素材集成"唯一值得做的真入口**——不接它，素材集成就是空话。
- **拟接入方式**：本地 REST API（`localhost:41595/api/v2`）。接入前先探 `/api/v2/app/info` 判断版本（需 Eagle 4.0 Build 21+，**待复核**）；本机调用免鉴权。
- **两个接入点**：
  - **写方向（归档）**：F13 交付成品 / F5 参考图，一键归档进 Eagle「约稿-单号」文件夹 + 自动打标签——与 F13 成品归档天然联动；
  - **读方向（选参考图）**：F10 录单或订单补参考图时，可从 Eagle 素材库直接挑图，取文件路径进 F5/F1——素材集成对录单的直接增益。
- **对桌面端功能影响**：素材集成有了落点；F10 录单可带 Eagle 参考图；F13 归档有了下游出口。与订单/委托管理主线零耦合，不侵入主链路。
- **预估成本**：中低。版本探测 + 读写两套调用 + "Eagle 没装/没开"的优雅降级（退回普通文件拖入）。
- **风险**：①版本门槛与目标画师装机版本分布**待复核**（立项前实测一次）；②Eagle 删除是软删除、部分端点绑新 build，集成以只增不删起步最稳；③必须 Eagle 运行中，降级设计是硬要求。
- **安全边界**：localhost 免鉴权、零凭证、不新增服务器攻击面；**不启用局域网 token、永不暴露公网**。脱网口径已拍板（824 用户）：脱网＝不碰公网，对本机本地应用的 localhost 调用不算公网请求——Eagle 集成在本地模式下可用。

### 首期-2：通用订单文件导入（CSV/Excel）

- **接入价值**：**死墙万能兜底**。米画师/画加/微信接单全部是死墙，但画师手里往往有表格或能导出表格——只要对方出得了 CSV/Excel，我们就进得来。同时覆盖 Ko-fi 历史订单补录（Ko-fi 无拉取型 API，官方路径就是 CSV 导出）。
- **拟接入方式**：文件导入。交互复用 F10 已拍板的「解析 → 预览 → 回填」三步口径；Ko-fi CSV 做第一个字段映射样例，其余格式画师手动对列。
- **对桌面端功能影响**：与粘贴解析/截图 OCR 并列为 F10 录单三条腿（粘贴=聊天单、OCR=截图单、文件=表格批量单）；本地模式记账（F2）也能批量导历史单。
- **预估成本**：低。纯本地解析，零第三方依赖、零网络。
- **风险**：字段格式漂移需维护映射表，但成本可控。
- **安全边界**：纯本地文件，无凭证无网络；导入落库后属"本地创建数据"，可导出，符合导出边界。

### 附带说明：剪贴板粘贴解析 + 截图 OCR

已随 F10 拍板，不算新增接入，但它是微信/米画师等死墙的**主力解决方案**——文件导入兜表格，OCR 兜截图，两条腿合起来死墙全有路。

## 四、二期候选（2 项）

### 二期-1：爱发电（国内订单回流）

- **接入价值**：国内唯一正规赞助/订单开放 API（调研评分 7.3），订单回流半自动化，省去手抄。
- **拟接入方式**：轮询式 API（query-order，MD5 签名），**仅云端模式、离线隐藏**；画师的爱发电 API 凭证存 Windows 系统保险箱（与平台凭证同口径）。
- **对桌面端功能影响**：订单/委托管理增量——云端模式下新单自动/半自动进订单列表，配合系统通知。
- **预估成本**：中。轮询调度 + 增量游标/去重 + 凭证保管。
- **风险与安全边界**：接口字段与当前可用端点清单**待复核**（调研报告复核项③：立项前人工进爱发电 dev 后台确认）；第三方密钥也进保险箱，不落明文。数据归属已拍板（824 用户）：爱发电同步回来的订单**视同本地数据**——可导出、切出账号后仍在、与手动记账同待遇。

### 二期-2：ICS 系统日历代写（已拍板，照列）

- 二轮拍板已定二期。本地文件写入、零网络、成本低，交稿提醒进画师手机日历。无争议项。

## 五、未来研判备案（824 用户拍板：现在不做）

### Ko-fi 实时订单（服务器 Webhook 中转）

- **拍板记录**：2026-08-24 用户拍板——加入未来研判，现在不做。
- **原方案要点**：海外约稿单实时推送（调研评分 8.5，免费零门槛）；但 Ko-fi 无拉取型查询接口，桌面端又已拍板不开监听端口，唯一路径是服务器加中转端点接收推送、桌面端经既有 REST API 订阅——属服务器改动，成本高。
- **当前替代**：Ko-fi 历史订单由首期「通用文件导入（CSV）」全覆盖，不接实时也无损失。
- **重评条件**：海外约稿实时性需求真实出现（画师反馈 Ko-fi 新单需要实时提醒），或服务器因其他需求已有中转能力时顺带评估；重评启动前先复核 webhook 事件字段与 token 路径（调研报告复核项①）。

### Bluesky 完稿宣发

- **拍板记录**：2026-08-24 用户拍板——做预留，全部功能做完后再考虑。
- **原方案要点**：F12 完稿宣传链的海外出口（评分 9.3，免费端点 + App Password，限流宽松）；官方 AT Protocol 端点发帖，仅云端模式，发帖前必须人工确认（永不静默代发）。国内用户（微博是死墙）不受益。
- **重评条件**：桌面端主体功能全部完成并稳定运营后，再评估是否纳入。

## 八、统一安全边界口径（适用于一切接入）

1. 桌面端永不开监听端口 → Webhook 一律转服务器中转、轮询或文件导入。
2. 脱网口径（824 已拍板）：脱网＝不碰公网；对本机本地应用（Eagle 等 localhost）的调用不算公网请求，允许。在线型接入仍全部仅云端模式、离线隐藏。
3. 凭证统一进系统保险箱：平台 token 与第三方密钥（爱发电等）同待遇，不落明文。
4. 数据边界：第三方同步进来的数据落本地库、视同本地数据可导出；平台数据仍不进导出；F8 工时数据与一切接入无关、永不上传。
5. 新增依赖登记 THIRD-PARTY-NOTICES（既有纪律）。
6. 降级纪律：对方程序没装/没开/接口挂了 → 退回手动通道，功能不消失、不报错。

## 十、取舍理由小结

- **首期只做 2 项的理由**：①本研判的使命是给 F10/素材集成的施工决策钉依据，不是开新战线——贪多会拖功能施工批主线；②Eagle 是唯一生态交集，错过它"素材集成"就没有真入口；③文件导入是成本最低、覆盖最广的通用通道，所有死墙都因此有路；④两项都零费用（免费路线）、零服务器改动（无排期依赖），正好卡进"更新通道收尾后、施工批启动前"的窗口。
- **二期放 2 项的理由**：订单回流类（爱发电）依赖云端登录体系与凭证保险箱先落地，天然排在后面；ICS 已拍板照列。Ko-fi 实时与 Bluesky 按 824 用户拍板进预留（Ko-fi 有文件导入覆盖无损失；Bluesky 等主体功能全做完再议）。
- **死墙不硬碰**：国内交易/沟通环节（米画师/微信）是结构性死结，桌面端定位就是"外围中枢"——用粘贴解析/OCR/文件导入做兜底，引导画师手动确认，不指望打通交易层（与调研报告战略结论 4 一致）。
