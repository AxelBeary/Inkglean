## 一、🟡 管理动作留痕补 IP 字段（迁移 v75）

**已核实现状**（`schema.ts:403` + `v59-compliance.ts:26`，REQ-042 v59）：

```sql
CREATE TABLE admin_actions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  admin_id INTEGER NOT NULL,
  action TEXT NOT NULL,        -- 下架/封禁/举报处理等
  target_type TEXT,
  target_id INTEGER NULL,
  reason TEXT NULL,
  created_at TEXT DEFAULT (datetime('now'))   -- ⚠ 只有时间
);
```

- **病灶**（9/12 路 3 登记，已核实属实）：验收标准写了管理动作要留"时间 / IP"，但表**只有 `created_at`（时间），无 IP 字段** → 出了纠纷无法追溯管理动作来源 IP。
- **改法方向**（施工会话据此出施工图，停等确认后再动）：
  1. **迁移 v75**：`ALTER TABLE admin_actions ADD COLUMN admin_ip TEXT NULL`，幂等（`PRAGMA table_info` 检查 `admin_ip` 不存在才加）。
  2. **`schema.ts:403` 同步**：`admin_actions` 的 `CREATE TABLE` 补 `admin_ip TEXT NULL`（保持新装/升级结构一致）。
  3. **写入点补 IP**：定位所有往 `admin_actions` INSERT 的地方（下架/封禁/举报处理各 action），写入 `admin_ip`（用上面既定取 IP 口径）。
  4. **测试**：断言动作留痕带 IP；覆盖"XFF 存在/不存在"两种取值；幂等迁移跑两次不炸。
- **🟡 为什么停等**：涉 DB 迁移（结构变更）+ 多处写入点，**无人值守自动改数据库是红线**。schedule 触发只出施工图（迁移文件草案 + 写入点清单 + 测试点），停等你确认。

- **病灶**（9/12 路 3 登记）：处理主页类举报时**做不了"下架主页内容"，只能整户封禁**（`is_banned`）——处置手段过粗，缺少中间档。

**待核清 + 待你拍边界**（施工会话出施工图前先查、并请你定）：
1. **`hidden` 态现有语义**：`artists.status` 已有 `hidden`，它当前是什么用途？是否已能承担"隐藏主页"？还是另作他用（如画师自己隐身）？**先核清代码里 hidden 的读写点**，别与"下架"语义打架。
