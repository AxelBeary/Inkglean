## 3. 可见性判定唯一事实源（新增 `server/src/features/artist/artist-visibility.service.ts`）

```ts
/** 主页对客户不可见 = 画师自助隐身 ∪ 平台下架（两者公开端表现一致，区分只在画师后台） */
```

## 4. API 契约

### 4.1 新增（全部在 `compliance.routes.ts` 内，自动继承 `registerAdminStepUpHooks` 的 `/api/admin` 前缀守卫——已核实 `step-up.ts:86` 按 `startsWith('/api/admin')` 匹配）

| 端点 | 入参 | 行为 | 留痕 action |
|---|---|---|---|
| `GET /api/admin/admin-actions` | `?limit=1..500`（默认 100）、`?action=`、`?targetType=`+`?targetId=` | 时间倒序，行内含 `admin_ip` | — |
| `POST /api/admin/artists/:id/home-takedown` | body `{reason?: string\|null ≤500}` | 置 `home_takedown_at`/`_reason`；**不 bump token_version**；幂等（已下架返回 200 不重复记） | `home_takedown` |
| `POST /api/admin/artists/:id/home-restore` | 同上 | 清空两列 | `home_restore` |
| `POST /api/admin/content/artwork/:id/restore` | 同上 | 清空 `takedown_at`/`_reason` | `content_restore` |

- **管理员账号不可被主页下架**（对齐既有 ban 口径 `compliance.routes.ts:160-163`，防锁死平台）。
- `removeContent` 的 artwork 分支从 `deleteArtwork()` **改为置 `takedown_at`**；message 分支不变。

### 4.2 改动

- `POST /api/admin/content/:type/:id/remove`：type 枚举**保持 `artwork|message`**（主页走 4.1 的 home-takedown，target_type 语义更清晰，不混用 remove）。
- 举报处理：`resolveReport` 保持原语义（只标 resolved）；主页下架由管理员**显式**点 4.1 端点（避免"处理举报即自动下架"的误伤面）。管理后台把 `artist_home` 举报行同时给出「封禁」与「下架主页」两个按钮 —— **属 P3**。
- 画师端 `GET /api/artist/profile`：响应补 `home_takedown: { at, reason } | null`，供 P3 做后台横幅（画师是权利人，可看原因）。
