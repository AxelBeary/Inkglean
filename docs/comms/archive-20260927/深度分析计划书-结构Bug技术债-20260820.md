## 一、分析范围与边界

### 1.1 三类问题定义

| 类 | 编号域 | 内容 |
|----|--------|------|
| ① 结构类（屎山） | S-xx | 巨型文件 Top 榜重建与职责混叠评分、死代码、重复实现、双模型分叉（同功能多实现且存在零调用路径）、隐式 any / @ts-ignore 蒙混、复制粘贴重复、模块分组合理性、循环依赖 |
| ② Bug 类 | B-xx / C-Mx | 主动扫描清单（六类高频陷阱）+ 组合场景矩阵（取消/重试/并发/权限切换/i18n/空值特殊字符/字段映射）+ STATUS 四条报障项逐条取证 |
| ③ 技术债类 | T-xx | 已记未清项逐项现状取证（是否已被历史批次部分销账、残留几何），区分「可接受暂缓」与「上线前必改」 |

### 1.2 明确排除（不做）

1. **不修任何代码**。发现 bug 只记证据、只给修复方向（一句话级），不给修复 diff——避免分析期诱导施工污染证据。
2. 不做视觉审美类评估（布局丑/间距问题等 812~820 批次已订口径项，不属本次三线）。
3. 不做覆盖率专项补测（除非某条 Bug 的取证必须靠新增临时脚本复现——临时脚本只放 `temp/`，不落产品目录）。
4. 不评估外部项目（oimimo）的功能对照——那是吸纳清单，不是本计划范围。
5. 不触碰数据库写操作；容器只读查询、不动数据。

### 1.3 全部角色无效区分禁区（红线）

- **禁**：修改 `server/src/**`、`web/src/**`、`e2e/**`、`server/scripts/**`、根 `scripts/**` 中任何产品/脚本文件（`git status` 每日核验，出现非文档改动立即回退）。
- **禁**：`npm install` 新依赖（madge 等工具一律不装；确需辅助工具时用 `temp/` 下的自写只读脚本，经一号点头）。
- **禁**：动数据库（含迁移、seed 重跑、DEMO 重置）；容器内一律只读连接（`readonly: true`）。
- **禁**：新建 git 分支 / worktree / commit（分析产物直接写主仓 `docs/comms/`，文档提交由一号统一执行一次）。
- **禁**：改 `docs/comms/STATUS.md`（一号专属）。
- **禁**：跑 `post-merge-deploy`、重建容器、重启服务。
- **允许并必须**：本地跑测试/lint/build（只读门禁命令）；跑 docker exec 只读查询；写 `docs/comms/` 分析报告；在 `temp/` 放辅助脚本与快照。

### 2.7 每项证据要求（缺失即不合格）

每条目至少携带以下之一（按类选配）：
- **代码类**：`file:line`（注明 master HEAD 短哈希）+ 关键行引用（≤10 行）
- **调用/死代码类**：全仓 grep 引用计数表（谁调用了、几次；零调用 → 附"导出但无引用"证据）
- **数据类**：容器内 DB 快照（`PRAGMA table_info` / SELECT 结果原文，附执行时间与容器 build 时间）
- **行为类**：复现路径（HTTP 请求序列或 UI 操作序列）+ 现象快照（API 返回原文 / 容器内查询佐证）
- **基线类**：测试数字原文（`Tests  N passed` 行、lint 0 警 0 错、build 输出行）
- **历史账目类**：`git log --oneline -- <file>` 轨迹 + 相关 STATUS 条目号

### 2.8 三态裁决与误报标注

每条发现必须落三态之一：
1. **属实**（当前 master 证据成立）→ 进待修复清单
2. **过时/已修**（历史已修，附 commit/STATUS 证据）→ 销账
3. **误报/设计意图**（如开发模式 `_dev_code`、白名单 SQL、既有拍板如"钱不进日报"）→ 误报表，附设计依据出处

外部清单与历史报告的照单全收是历史事故（"审计快照是快照"教训）。**逐条对照后裁决，不硬归账。**

## 五、扫描任务书细则

### 5.1 结构类（S）

**S-01 巨型文件 Top 榜重建与职责混叠评分**
- 起步事实（本计划书起草时实测，见附录 A1，执行前自行复测一遍并记录 HEAD）：
  - server ≥800 行：`server/src/features/admin/admin.routes.ts` 970、`server/src/features/pricing/style.service.ts` 938
  - web ≥800 行（排除 locales/api 数据型文件）：`ArtistManage.vue` 1040、`QueueBoardCalendar.vue` 972、`PriceCard.vue` 930、`OrderDetail.vue` 925、`ArtistLayout.vue` 902、`Login.vue` 879、`ArtStyleManager.vue` 867、`ManualOrderRight.vue` 865、`TplGallery.vue` 854、`QueueBoardList.vue` 836、`ArtworkManage.vue` 814
- ⚠️ **关键对照轴**：查 `git log --oneline -- <file>` 的拆分史（OrderDetail 曾 1450→628、QueueBoardCalendar 1326→756、ArtStyleManager 拆分过、OrderForm 1148→拆分）——**实测显示拆分后再次膨胀回 900+**，这是"屎山再生长"证据链，报告要给出"因哪几批功能回灌"的轨迹。
- 判定：对每个 ≥800 行文件做职责分段注释（每 100 行一个主题标签），输出「可拆分区段建议」一行级（如"L100-300 画师 CRUD → 抽 artist-crud.service.ts"）；不做拆分实现。
- 证据：行数实测 + `git log` 轨迹 + 职责分段表。

**S-02 死代码与零调用路径**
- 模式：对每个 `export`（函数/常量/组件）做全仓引用计数（grep 符号名 + LSP findReferences 双轨）。
- 判定：引用 0 = 死代码候选（区分：测试内引用 / migration 引用 / 字符串匹配误报）。双模型分叉专项：同功能两份实现（如两套金额格式化、两套 sanitize、两套时间格式化），列调用方分布；**一份实现调用为 0 = 孤儿实现**（先例：档位死 API 前后端 6+6 条一次性清理）。
- 证据：引用计数表 + 调用方 file:line。

**S-03 隐式 any / @ts-ignore / ts-expect-error / 复制粘贴退化扫描**
- 模式：`\bany\b`（重点 `as any`、`: any`、`<any>`）| `@ts-ignore` | `@ts-expect-error` | 大段相似代码块（同一文件内 50+ 行两段相似 → 复制粘贴嫌疑）。
- 判定：v132 全仓 TS 迁移后应有 **0 any / 0 抑制注释**（基线声明）——任何命中 = 退化事件，标 🔴（纪律回归）待复盘。复制粘贴段标 🟡 并给出抽象建议一句话。
- 证据：命中清单 file:line + 上下文 5 行。

**S-04 模块分组合理性与循环依赖**
- 模式：对照 `server/src/features/` 与 `web/src/` 目录树，检查跨域 import（如 order 域 import pricing 域直接读私有函数、web 组件跨 views 深层 import）；循环依赖用 `temp/` 静态 import 图脚本（读 import 语句建边，DFS 找环；**不装 madge**）。
- 判定：环形依赖 = 🟡（说明环路径与圈定修复方向）；`features/<a>/x.ts` 被 `features/<b>/*` 直接深 import 而非经公开接口 = 🟡 结构债。
- 证据：环路径图 + import 边清单。

**S-05 迁移链与 schema 一致性（B 线）**
- 模式：`server/src/db/migrations/` 全部文件链表完整性（版本号连续、v64 起幂等守卫存在、含备份的迁移声明 noTransaction）；DDL 双轨（完整 schema + 迁移链）一致性由测试锁定——复跑 vitest 中 schema 一致性测试确认。
- 证据：迁移清单表 + 测试通过数字。

**S-06 scripts / e2e 脚本侧结构（B 线）**
- 对象：根 `scripts/*.ps1/*.mjs/*.sh`、`server/scripts/*.ts`、`e2e/**`。
- 模式：覆盖缺口检查（哪个脚本无人调用/CI 不挂、哪个产物无人消费）；e2e fixture 与真实现状漂移（列名、路由、locator 陈旧）。
- 证据：引用计数 + 与 CI yml 交叉对照。

### 5.2 Bug 类（B）

**B-01 .toFixed() 空值崩溃（前端）** — 模式 `\.toFixed\(`，判定：调用值必须可证数字或有 `?? 0` 保护；来自 API 且裸调 = 潜在崩溃 → 🟡/🔴（按触发面）。

**B-02 parseInt 无基数（前后端）** — 模式 `parseInt\([^,)]+\)`，判定：路由参数（Fastify schema 已约束）记 🟢 记录级，他处一律要求补基数建议。

**B-03 静默空 catch（前后端）** — 模式 `\.catch\(\s*\)|catch\s*\{\s*\}`，判定：前端零容忍=🟡；后端仅 GC/清理类可带注释豁免，余额 = 🟡。

**B-04 v-html 漏消毒（前端）** — 模式 `v-html`，判定：数据源必须过 `sanitizeHtml`，裸绑定 = 🔴（XSS 前科在册）。

**B-05 路由鉴权覆盖（后端）** — 模式：全部 `*.routes.ts` 的 preHandler/onRequest 注册清单；判定：`/api/admin/*` 必挂 requireAdmin+step-up、画师写路由必挂会话、公开路由（客户查单/主页）凭证走令牌/anon-token；任何裸奔 = 🔴。
