## 一、前置校验（不满足就停下报你，不硬收口）

1. **ledger 齐全**：`ledger_P1.md`~`ledger_P4.md` 都在（P1~P4 各自触发过）。缺哪份 = 哪批没跑或没落 ledger → 停下报你，不替它补做。
2. **前序门禁绿**：各 ledger 记录的端门禁结果都是绿（P3 web、P2 desktop、若 P4 施工了则 server）。**任一前序批门禁未绿 → 停下报你**，不带病收口。
3. **收口范围界定**（关键）：本批只收口 **P1~P4 已完成的 🟢 部分**——P1 文档、P2 的 F-33/F-07/卷心 inert、P3 的三处小修。各批的 **🟡 停等项**（P2 波 2、P3 F12、P4 两项）**若你尚未确认施工，则标注"施工图已出待确认，未纳入本轮收口"**，不阻塞 P5、不代入门禁。

**回写 `docs/comms/STATUS.md`**：

- **遵守体例**（AGENTS.md）：单行 ≤200 字；新条目写成"短标题 + 分组要点"，**禁止把整批结论塞进一个长行**（超长行会让 ripgrep 漏报、diff 不可读、精确替换易错）。
- 🔴 **不做归档搬动**：STATUS 正文现已远超"只留最新 5 条"体例（这本就是 G8 红灯登记项）。P5 加新条目后**不顺手把第 6 条起搬进 `archive-YYYYMMDD/`**——文本搬动属高风险迁移，须你确认后**单独一批**做，完事用"字符总量前后差 + 逐条比对"校验零丢失。P5 只在收口条里**标注一句**"正文已超体例 5 条，待 G8 归档批处理"。

## 四、全量门禁 accept.ps1（17 道）+ 同步基线

1. **同步 `scripts/accept-baseline.json`**（跑 accept 前先做，否则假红）：若 P3 补了设备测试、P2 补了卷心 inert 断言、（若施工了）P4 加了迁移测试，用例数会变——把 server/web/desktop/shared 的数字改为**各 ledger 记录的实测值**，history 写明"哪批涨了哪些"。⚠ 9/12 曾漏同步 baseline 导致下次 accept **假红**，本批务必先同步。
2. **跑 `pwsh scripts/accept.ps1`**（17 道全量，含 E2E 与防阀）：需本地环境就绪（Docker/服务，E2E 走 5059 或既定端口）。**完整贴出输出**（各端测试数、lint 零错误、防阀"豁免 0 项"、E2E 13 例）。
3. **判读**：17 道全过 = "门禁全绿"；带 `-SkipE2E` 时 15 道，须写明"（跳过 E2E）"，不得称全绿。

## 五、提交待令（不自动 push）

- 门禁全绿后，**汇总本轮改动**（P1~P4 已完成部分 + P5 的 shared/STATUS/baseline），生成 commit message 草稿，**提交待令**。
- **等你明确下令才 `git commit`**；`git push` 更需你单独下令（push 后才会触发 CI 四 job + E2E + CodeQL）。
- 提交前按纪律**核文件归属**：`git status` 逐条确认都是本轮 P1~P5 领地文件，**禁 `git add -A` 误扫并行会话在途代码**（共享工作区纪律）。若发现非本轮的未跟踪文件（如别的会话在途件），不纳入本次提交。
