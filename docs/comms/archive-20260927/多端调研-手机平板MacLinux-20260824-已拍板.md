## 二、手机端

### 2.1 先想清楚：手机上做什么？

桌面端的立身之本是**本地优先**（管本地文件、本地记账、本地时间统计）。但手机的文件系统是封闭的——画师不会在手机上管理 CSP 工程文件。所以手机端的定位和桌面端**不是同一件事**：

- **手机适合**：云端随身看——排期/待办瞄一眼、截稿倒计时提醒、新订单/留言通知、收入速览、快查卡。全是已登录云端模式的功能。
- **手机不适合**：F1 文件管理、F8 窗口自动识别（手机没有"前台窗口标题"可监听）、本地记账的桌面式体验。
- 推论：手机端 = **纯云端轻客户端**，桌面端「双模式完全分离」纪律里的本地模式世界在手机上不存在。这不是缺陷，是手机形态本来如此。

### 2.2 三条路线

**路线 A：PWA（把现有网页"装"进手机桌面）—— 调研建议的首选**

- 做法：给现有 web 加 PWA 底座（manifest 清单 + Service Worker + 图标），画师用浏览器打开网站 →「添加到主屏幕」→ 从此像 App 一样全屏打开、有独立图标。
- 优点：
  - 复用现有 web 代码，不引入任何新技术栈；
  - **零商店合规压力**：它还是网站，不涉及国内 App 备案/软著/商店审核（见 2.3）；
  - 零费用：不用 $99 苹果年费、不用安卓商店账号；
  - 推送：Android 完整支持；iOS 16.4+ 支持（前提是已添加到主屏幕，已核实）。
- 代价（诚实清单）：
  - 现有画师后台是**桌面优先**设计（页面宽度默认按 1000px+ 布局），手机窄屏要做一轮**响应式改造**——这是 PWA 路线的主要工时，不是加个 PWA 壳就完事；
  - iOS 上 PWA 的后台能力受限（无静默推送、存储有配额），够"看"不够"干重活"；
  - 「添加到主屏幕」需要引导一次（下载页/后台内提示）。
- 现状核实：web 目前**没有** PWA 底座（无 manifest、无 Service Worker），需从零搭，但这是标准活。

**路线 B：Tauri 2 手机壳（原生 App，同一套代码）**

- 事实：Tauri 2.0 起官方稳定支持 iOS/Android（2024-10 稳定版发布时宣布，已核实）；官方插件（SQLite、键值存储、通知、生物识别等）覆盖移动端。
- 但是（诚实清单）：
  - **iOS 构建必须有 Mac + Xcode**（硬约束，绕不开）；
  - **iOS 上架必须 $99/年** 苹果开发者账号，中国区还要 App 备案（见 2.3）；
  - **Android 渲染碎片化**：依赖用户手机上的系统 WebView 组件，旧机型可能样式崩坏（已核实，官方与社区均提示）；
  - 官方自述移动端开发体验仍在打磨中，不如桌面端成熟（已核实，官方 2.0 发布原文）；
  - 桌面端已拍板的 F8 窗口识别、托盘、全局快捷键等在手机上**全部不存在**，等于手机壳只承载云端功能——花原生 App 的成本，只为 PWA 也能做到的事，性价比存疑。
- 何时重评：若未来「手机离线看订单快照 + 原生强通知」成为硬需求，再回来看这条路。

**路线 C：另起技术栈做原生（Flutter/小程序等）—— 不推荐**

- 与既有技术栈（Vue 3 + Tauri）完全分家，维护第二套骨架，违背同仓复用纪律；小程序还要接微信生态合规。除非出现颠覆性理由，此路封存。

### 2.3 国内上架合规（路线 B 才会撞上，如实记录）

已核实（2025~2026 多篇上架实录交叉印证）：

1. **App 备案**：国内上架（含苹果中国区）必须先完成工信部域名备案 + 全国互联网移动应用程序备案，无备案上不了架。个人主体**可以**备案，但仅限**非经营性工具类**；经营性必须企业主体。
2. **软著**：国内安卓商店普遍要求《计算机软件著作权》（免费申请但慢，约 30~40 工作日）。
3. **商店主体门槛**：华为允许个人上架；小米、OPPO 等要求企业主体。政策在变，拍板时需重新核实当时口径。
4. **绕开商店的替代路**：官网直接下载 APK（不上商店可避开商店资质审核），与桌面端「官网下载」分发模式同构；代价是国产手机对非商店 APK 有安全警告与安装限制，体验打折。

### 2.4 手机端调研建议

- **先 PWA 后 App**：PWA 路线把「响应式改造」这笔工时花出去之后，无论将来是否做原生壳都不浪费（原生壳里跑的也是同一套网页）。
- 顺序上仍排在桌面端功能批之后。

## 三、平板端（iPad / 安卓平板）

**结论：平板不构成独立决策项，跟手机路线同进退。**

- 平板上画师的需求画像 = 大屏版手机：躺沙发/离开工位时看排期、看留言、看收入。绘画软件（Procreate 在 iPad、CSP 平板版）与我们无关。
- 若手机走 PWA：平板用浏览器加到主屏幕即得，响应式改造天然覆盖平板宽度。
- 若手机走 Tauri 移动壳：iPad 跑 iOS App / 安卓平板跑安卓 App，同一产物直接覆盖。
- 因此本调研不单列拍板项，平板自动继承手机拍板结果。

## 四、macOS 端

### 4.1 技术面（可行，REQ-014 二期备案的延续）

- Tauri 2 原生支持 macOS（系统 WKWebView），同一套代码库，打包出 .dmg/.app。
- 已拍板的自托管静默更新（tauri-plugin-updater）**支持 macOS**，Ed25519 验签口径可直接复用。
- 需要做的适配（诚实清单）：
  1. **WebKit 样式验证**：macOS 的内核是 WebKit（与 Windows 的 Chromium 不同），REQ-014 早已备案届时要验证。好消息：web 项目目标浏览器本就含 Safari，有底子在，但桌面壳内要实测一轮。
  2. **平台习惯差异**：macOS 没有"开机自启到托盘"的同款概念（用 Login Items / 菜单栏），全局快捷键、窗口贴靠语义不同。
  3. **F8 窗口识别**：macOS 枚举窗口标题需要**辅助功能权限**（用户要手动授权一次），可做但要加引导。
  4. **凭证保险箱**：对应 macOS Keychain（与 Windows 系统保险箱口径一一对应）。
  5. **文件路径**：`我的文档\拾绘\` 概念换到 macOS 用户目录，文案与引导要跟着改。

### 4.2 分发与签名（最大成本点）

已核实（Apple 官方文档）：

- macOS 10.15 起，App Store **以外**分发的软件必须 **Developer ID 证书签名 + 苹果公证（notarization）**，否则 Gatekeeper 拦截（用户要进系统设置手动放行，体验比 Windows SmartScreen 更劝退）。
- Developer ID 证书**只发给付费的 Apple Developer Program（$99/年）**，**没有免费渠道**——桌面端的 SignPath 免费签名路线是 Windows 专属，**在 mac 上没有对应物**。这是与免费路线偏好冲突的硬支出，需要用户拍板。
- 备选（回退方案，对标桌面端备案 B）：不签名 + 下载页"右键→打开 + 系统设置放行"图文教程。可行但转化率难看。
- 工程约束：**构建与签名需要 Mac**（本机或 CI；GitHub Actions 公共仓 macOS 构建分钟免费，可零成本解决）。

### 4.3 macOS 调研建议

- 技术上是四端里"最顺理成章"的一端（同代码库、更新通道复用、REQ-014 有备案）。
- 唯一真决策点：**$99/年签名费** 接不接受。接受 → 排期在桌面端功能批之后做；不接受 → mac 端无限期备案，给需要的人指"浏览器用网页版"。

## 五、Linux 端

### 5.1 事实

- Tauri 2 支持 Linux（系统 WebKitGTK），打包 .deb / .rpm / .AppImage。
- **分发完全免费**：官网下载（同桌面端模式）或上 Flathub 等社区商店（免费）；**无签名要求**。
- CI 免费：GitHub Actions 公共仓 Linux 构建分钟免费。
- 与 macOS 同为 WebKit 内核家族——**样式适配验证可以和 mac 一次做完，两头共用结论**。

### 5.2 诚实清单（坑先摆出来）

1. **用户画像最弱**：国内画师主力软件（CSP/SAI）没有 Linux 版，Linux 画师基数极小——做它是"顺手"，不是"有需求拉动"。
2. **F8 自动识别做不了**：现代 Linux（Wayland 会话）不提供全局窗口枚举能力，F8 的"自动识别在画哪个文件"在 Linux 上只能退化为手动计时。若做，文案要如实。
3. **系统依赖**：用户机器要有 webkit2gtk 4.1 库（deb 包可声明自动装；AppImage 自带但包体变大）。
4. **托盘图标**：GNOME 桌面默认不带托盘支持，"托盘常驻"体验在部分发行版上会缺角。

### 5.3 Linux 调研建议

- 备案「顺手做」：若 macOS 样式验证都做了，Linux 只差打包配置，边际成本接近零；若 macOS 不做，Linux 更没理由单独做。
- 定位：开源社区形象分 + 少数派兜底，**不设时间承诺**。

## 六、安全口径映射（桌面三条口径 → 四端怎么套用）

桌面端开工前强制基线的三条口径，四端照抄映射，**后端不需要再动骨架**：

| 桌面口径 | 四端套用 |
|---------|---------|
| ① 记账式会话 + 设备账本（迁移 v73 已落地） | 直接复用：会话已带 `client + device_id` 字段，手机/平板/mac/linux 各记各的账，踢人/顺延同逻辑。凭证保险箱对应物：iOS Keychain / Android Keystore / macOS Keychain / Linux Secret Service（gnome-keyring）——各端插件覆盖度拍板后实测 |
| ② CF 免验证通道只免登录类接口；身份标签可伪造、非防线 | 同一本手册扩容：身份标签扩展 `X-Shihui-Client: mobile/平板/…` 各值，落档口径不变（仅分流统计，绝不做放行条件） |
| ③ 更新防投毒三件套 | mac/Linux：updater + Ed25519 验签原样复用。iOS：走 App Store 本身即平台托管（或不上架）；Android：若官网 APK 直发，需自制"下载新包→覆盖安装"流程，验签纪律照搬 |
