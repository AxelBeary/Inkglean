### 🔴 F-01 图片归档校验和错误 → 备份实际不可用
- **类型**：代码 bug（非文档）。
- **文件**：`server/scripts/backup-uploads.ts` `tarHeader()` L67–84。
- **根因（主代理已实测复算坐实）**：L76–77 先对 512 字节求和、L78 写入校验和，**之后** L79–82 才写 `typeflag`(156)、`magic`(257)、`version`(263)、`prefix`(345)。POSIX 要求这四个字段计入校验和。归档实测：存的 `014557`＝代码顺序复算值（模型吻合），标准要求 `016056`。
- **改法（已按此完成）**：把求和与写入校验和这两步**移到最后**（ L82 之后）。实际落地代码：
  ```ts
  buf.write('        ', 148, 8)          // 校验和字段先填 8 空格
  buf.write('0', 156, 1, 'utf8')          // typeflag
  buf.write('ustar\0', 257, 6, 'utf8')    // magic

  buf.write(prefix, 345, 155, 'utf8')     // prefix
  let sum = 0
  for (let i = 0; i < 512; i++) sum += buf[i]
  buf.write(`${sum.toString(8).padStart(6, '0')}\0 `, 148, 8, 'utf8')
  ```

### B8 实测结论（9/5 主代理用 `temp/recon-server-test.log`（9.9MB，数字实测路留下的全量测试输出）核实）

- **「未 await 的 rejects 断言」＝1 处**（全日志仅 1 条）→ 与二审「逐行核实后真值 1 处」一致，**初报的「7 处」确认为启发式 grep 误判**（6 处是跨行 `await expect(...)` 合规写法）。归属仍是 `server/tests/publish-artwork.test.ts:169-170`。Vitest 3 仅警告、升 4 判失败 → 属升级前必修的一行。
- **`MaxListenersExceededWarning` 实为 66 条，且涉及三类监听器**：`uncaughtException` / `unhandledRejection` / **`beforeExit`**。→ 修正两件事：①「22 个 worker 各一次」不准，66 ≈ 22 worker × 3 类；②**其中 `beforeExit` 不是本仓代码注册的**（`server/src/index.ts` 只挂了 uncaughtException / unhandledRejection / SIGTERM / SIGINT），它来自测试运行链自身（tsx/vitest 子进程），**不得归因到产品代码**。
- **因此修法口径需收窄**：把 `server/src/index.ts:34/42/77/78` 的监听器注册收进显式 start 路径，只能消除其中两类告警；`beforeExit` 那一份得单独判断是否源自测试工具链（否则会被当成“改了产品代码就能清完”）。本项仍属技术债、不影响当前门禁结果。
