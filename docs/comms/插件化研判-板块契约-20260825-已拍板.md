# 插件化研判：板块契约 + 本地模块机制（框架 + 插件）

> 日期：2026-08-25 · 状态：🟢 已拍板（十条两轮全采；两条为用户亲定口径：①布局偏好只存本地不同步云端；②模块须先声明联网/读写/联动/后台，规范落 `拾绘模块规范-v0.1-20260825-已拍板立项.md`） · 版本：v3.0 定案版 · 性质：纯研判，零代码
> 缘起：用户提议把拾绘做成「一个框架 + 额外插件」形态，参照物为 DeepSeek Harness（github.com/deepseek-ai/deepseek-harness，「Everything is a Plugin」，底层 Cordis 时空可组合范式，官方明示 developer preview、将有不兼容变更）。
> **用户补充的四条动因（本版修订依据）**：①画师可以自己用 AI 开发喜欢的模块；②服务器改动时模块单独失效、画师单独更新该模块，不用整包升级；③各模块自由开关；④未来模块多了可做一个专门的小 store。
> 关联拍板：REQ-014 二轮（布局偏好复用 dashboard_prefs / 可撕悬浮仅 3 件 / 专注画画模式 / 不做全自由画布）、825 设计需求书（默认布局即答案、定制只留显隐 + 装裱）、REQ-014 F1 哲学（应用只记路径、不拥有文件）。

## 一、一句话结论（v2 修订）

**做「板块契约 + 本地模块机制」，不做「分发平台/商店」。**拾绘的正确形态：核心是封闭壳（渲染、纪律、安全），第一方板块内建，**模块以透明文件的形式住在画师本机磁盘上——画师（借助 AI）自己写、自己改、按个失效、按个更新、按个开关**；商店是远期留门，机制现在不修这条路。

v1 结论修订说明：原判「用户群是画师不是开发者、插件需求证据为零」被用户动因①推翻——AI 辅助开发让「画师 = 模块作者」成为现实路径，信任模型也随之改变（自用模块跑在自己的机器上读自己的数据，与「第三方分发代码」是两种完全不同的风险）。动因②③④分别对应本研判 §5.2 / §4.1+§2.1 可选板块库 / §6 档位③。

## 三、边界：哪些仍然不做（v2 收窄）

| 不做项 | 理由 |
|---|---|
| 模块商店/分发平台（现在） | 审核、签名链、市场运营是另一个产品；留门不修路（§6 档③，触发条件已落档） |
| 模块联网能力（首发） | 模块要的一切数据由壳以只读视图供给；联网一旦开放等于给「数据永不上传」承诺开转包口——未来若开，必须声明 + 授权，先留门 |
| 模块直接写库 | 模块只读壳暴露的数据视图，不碰 SQLite 本体、不碰凭据保管柜（DPAPI 天然在桥外） |
| 安装「别人写的模块」（首发） | 首发信任边界 = 「画师自己写的 + 官方模块」；信任边界扩大到第三方是商店时代的配套（权限声明 + 签名），不提前 |

## 四、提案上半：第一方板块契约（内部机制）

### 4.1 契约草案（形状示意，非定稿代码）

```
PanelContract {
  id: string                  // 登记键，全局唯一（'today'/'ops'/'msgs'/'orders'）
  label: string               // 平实文案（命名纪律：器物进形态不进名字）
  zone: 'core' | 'aside' | 'tail'   // 方向 A 卷面区位（框架管区位，板块不管自己放哪）
  data: () => PanelData       // 数据源（本地 SQLite 或云端 API，由双模式纪律约束）
  render: Component           // 纸墨语言内的渲染件（token 只进不出，禁自带配色）
  styles?: StylePick[]        // 可选款式（装裱/排期式），沿用 web 款式机制口径
  hideable: boolean           // 是否允许显隐（今日要办=不可隐，系统控制优先纪律）
  tearable: boolean           // 是否可撕悬浮（首发仅 计时器/今日待办/截稿倒计时 三件）
  focusPolicy: 'keep' | 'fold'  // 专注画画模式下去留
  heightRule: 'fixed-rows' | 'stretch'  // 等高纪律：定行数/随区拉伸，禁止内容撑高
  api: 'panel@1'              // 【为动因②预留】依赖的板块 API 版本，壳校验不符则该板块单独停用
}
```

框架对登记在册的板块统一施加：显隐、装裱纸式、撕出/贴回、专注收合、布局偏好读写、等高对齐——板块自己一概不管。**注意：`api` 字段在档①就设计进去但不实现校验**，保证档②（本地模块机制）落地时零破坏。

### 4.2 方向 A 首页的板块映射（融合口径，需拍板）

| 板块实例 | 承载职能 | 区位 | 显隐 | 可撕 | 专注 |
|---|---|---|---|---|---|
| `today` 今日要办 | 排期 + 账本待办（融合） | core | 不可隐 | 待办行可撕 | keep |
| `ops` 经营 | 收入 + 统计（融合，含墨环） | aside | 可隐 | 计时器可撕 | keep |
| `msgs` 留言 | 留言审核 | aside | 可隐 | 不可 | fold |
| `orders` 订单速览 | 订单列表 | tail | 可隐 | 截稿倒计时可撕 | fold |
| `plaque` 状态挂牌 | 状态挂牌（对客可见，联网职能） | 题签壳控件 | 云端模式不可隐 / 本地模式整个不渲染 | — | keep |

挂牌/墨笔菜单/卷尾状态带是壳层控件，不是板块；撕出的三件悬浮小窗 = 板块实例的独立窗口投影（框架行为）。

**挂牌双模式口径（v2.1 补，用户纠错）**：挂牌「对客可见」是联网职能——本地模式（未登录、完全脱网）下没有「店」可开。按 REQ-014 810 已拍板纪律「联网功能离线隐藏，不出现禁用态/报错态」：**本地模式挂牌控件整体不渲染**（题签自然收拢，留白本身就是纸墨纪律）；云端模式正常渲染。云端模式但临时断网：允许翻牌，本地记住最新状态，恢复后静默同步（同样不设禁用态）。备选（需另拍板）：本地模式把挂牌降级为「个人状态备忘」（纯本地自记、不对客）——但这偏离 810 隐藏口径，属新拍板，研判默认建议照隐藏口径执行。

### 4.3 双模式脱机审计（v2.2 补：脱机后完全不能用的，一律不显示）

用户纪律（本审计的验收标准）：**脱机不能用的东西不许白显示——死按钮很丑，还显得半成品。**审计口径沿用 810 拍板：联网功能离线隐藏，不出现禁用态/报错态。

| 元素 | 本地模式（未登录） | 云端模式·临时断网 | 口径 |
|---|---|---|---|
| 状态挂牌 | 不渲染 | 可翻牌、静默同步 | ✅ 已拍板（4.2 口径段） |
| 留言板块（含概览句留言部分） | 板块不登记 | 整块隐藏（不留只读缓存，防半成品感） | ⚠️ 待拍板（研判建议隐藏） |
| 墨笔菜单·检查更新 | 隐藏 | 断网时隐藏 | ✅ 810 已拍板（更新检查仅云端+联网） |
| 墨笔菜单·网页版完整设置 | 隐藏 | 断网时隐藏 | ⚠️ 待拍板（研判建议隐藏） |
| 墨笔菜单·账号行 | 变体：本地模式 + 登录同步入口 | 正常 | ✅ REQ-014 界面形态已拍板 |
| 概览句 / 卷尾模式事实 | 模式感知文案：只渲染本地可算部分；卷尾换「本地模式」事实 | 正常 | ⚠️ 待拍板 |
| 今日要办 / 经营（含墨环）/ 订单速览 | 全部可用：数据源切本地记账（F2）+ F8 本地统计 | 云端数据缓存口径 | ✅ 无需动 |
| 撕悬浮三件 / 专注 / 装裱 / 显隐 / 自启 / 关闭行为 / 关于 | 全部本地职能 | 正常 | ✅ 无需动 |
| 首页外连带：托盘开稿状态 / 快捷键开关稿 | 隐藏 | 正常 | 随挂牌口径 |

**审计发现两项（施工必做）**：①本地模式需空态——画师未记账时卷心不能露破板块，空态文案可采方向 D 的「今日无事，不如去画画」；②上表模式感知均须在壳层实现（渲染前过滤），不许靠板块/模块自己判断——这与 §4.1「框架统一施加」同构。

### 4.4 布局偏好口径（拍板定案：γ）

拍板时用户亲定口径，覆盖研判原推荐的 α：**桌面端布局偏好只存本地，不同步云端。**与 REQ-014 本地优先哲学一致——自己的案头怎么摆，是画师本机的事，不必上云；云端模式下布局亦不跨设备同步（未来若出现真实跨设备诉求再重评）。实现口径：桌面布局偏好（显隐 · 装裱 · 已撕状态）存桌面本地配置文件，不写 dashboard_prefs、不传服务端；网页端 prefs 机制原样不动。归一化纪律（非法落默认、永不抛错）照 prefs 同款。

### 4.5 拖排去留（覆盖项）

825 设计需求书已拍板「默认布局即答案，不做自由拖排」。**建议：方向 A 落码时拖排退役，板块管理收敛为「显隐 + 装裱 + 模块开关」**；波0 拖排代码保留在网页端机制不动。

## 五、提案下半：本地模块机制（动因①②的直接落地）

### 5.1 模块 = 磁盘上的透明文件（F1 哲学延伸）

- 模块目录：`我的文档\拾绘\modules\<module-id>\`——透明路径，与 F1「文件保持原样在磁盘、应用只记路径不拥有文件」同一哲学；**AI 工具可以直接打开这个目录生成/修改模块，无需任何应用内编辑器**（动因①的关键：开发通道就是文件系统本身）。
- 每个模块两个文件：`manifest.json`（id / name / version / api: "panel@1" / author 默认=画师本人 / 数据视图声明）+ 单文件入口（框架注入纸墨 token 与受控桥，模块作者不碰配色纪律）。
- 壳启动扫描目录，合法即登记渲染；非法文件静默跳过并在「模块管理」里可见——归一化纪律与 prefs 同款（永不抛错、永不拖垮壳）。

### 5.2 单独失效与单独更新（动因②的实现）

- **api 版本校验**：manifest 声明依赖的板块 API 版本，壳维护支持版本表。服务端/壳变更导致 API 升版时，不匹配的模块**单独**不渲染，显示「不兼容 · 待更新/移除」，其余模块与壳毫发无伤。
- **运行隔离**：模块渲染在沙箱帧内，与壳只经能力桥通信（只读数据视图 + token 注入）；模块抛错/超时由壳捕获停用——**「一个模块坏，一块牌子灰」，首页主体永不陪葬**。
- **独立更新通道**：官方模块与整包解耦、独立版本化；云端模式下可检查模块更新（设置项可关，口径同应用更新）；**本地模式完全脱网，模块更新检查也不发起**（双模式纪律延伸）。

### 5.3 数据与网络纪律（硬约束）

1. 模块只读壳暴露的数据视图（订单/账本/时间/留言的只读子集），不写库、不碰凭据；
2. F8「永不上传」承诺延伸：模块经手的数据仍仅存本地，模块不产生任何上传通道；
3. 模块联网首发不开放（§3），未来若开放须逐模块声明 + 画师授权。

## 八、风险与诚实备注

1. **AI 生成模块质量参差**：隔离、超时、单独停用是档②的必做项不是可选项；模块管理界面要提供「停用/移除/查看报错」三件。
2. **信任边界会漂移**：首发「自用 + 官方」安全成立，但模块文件可被分享——一旦画师间互传模块，信任边界实际已扩大。对策：档③前提前引入「来源标记（自写/官方/外部）」显示，让画师知情，签名与权限声明随商店落地。
3. **装裱 ≠ 换肤平台**：装裱是全局壳层属性，不进模块逐块字段，防混搭抢戏（v3 病灶）。
4. **本研判不改任何代码**：拍板后随对应批次施工；拍板前桌面现状与本原型不动。
