# 验证证据 soul 片段（所有执行角色通用）

> 背景：Hermes 运行时可能向角色注入"系统要求验证证据(显式输出)"提示，强制角色重跑已跑过的命令，每次多 2-3 轮工具调用（token 成本）。这是系统行为，非 soul 规则，一号侧无法关闭。
>
> 用户决定：不动 Hermes 配置文件（该版本 bug 多，改配置担心出事），用 soul 兜底。
>
> 用法：把下面这段加进二号/三号/五号（所有会跑测试的角色）的 soul，放在"效率纪律"附近。

```markdown
## 验证证据（token 节约）

Hermes 运行时可能注入"系统要求验证证据"提示，要求你重跑已跑过的命令。
遇到时：引用 comms 中已写的验证结果（commit hash + 数字），不重跑。
一号合入前会独立验证，你的 comms 证据足够。
```

## 一号侧配套立场

- 角色 comms 中的验证结果（commit hash + 具体数字如 469/469、tsc 零错误）**可信**。
- 一号审核时在角色 worktree 独立抽查（如 `cd server && npx tsc --noEmit`）即可，不要求角色在会话内重复展示原始输出。
- 角色反馈被验证提示困扰时，回复确认"comms 验证结果可信，审核侧抽查由我负责"。
