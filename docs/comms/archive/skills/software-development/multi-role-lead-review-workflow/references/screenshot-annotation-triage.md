# 用户带标注截图分诊（圈/问号 = "这是什么 / 是不是有问题"）

<user>是非程序员，高频用「截图 + 手绘标注（橙圈、问号）」提问。标注本身不说明意图——圈可能是"这是干嘛的"，也可能是"我觉得这里不对劲"。**两者都要覆盖**：先解释清楚，再主动把该区域审一遍。这是本用户最核心的反馈形态（"点评即最高优先级 Brief"），处理好了能直接从疑问里挖出真 Bug。

## 标准流程

1. **像素级定位每个标注**：`browser_navigate` 打开图片（file:// 本地路径），再 `browser_vision` 提问，明确要求"逐个回答注释放哪、上下左右参照物、相对位置到像素级"。一次把圈+所有问号都问到，别只问一个。
2. **映射到代码**：标注指向的 UI 元素 → `search_files` 找承载组件（如手动录单=ManualOrder.vue）→ 读 template 确认该字段/控件。
3. **解释这是什么**：用代码事实回答"它是干嘛的、有哪些规则/上限、为什么放在这个位置"（引用 REQ 设计意图更好）。
4. **主动审计（关键增量）**：别停在解释。把该元素及其同族逻辑审一遍，找真问题——尤其下面两类高发模式。
5. **结构化汇报 + 先问再修**：给"标注是什么 → 查出哪些真问题（分档表格 file:line）→ 修复建议与风险评估"，结尾明确问用户"只是想弄明白，还是要我修"。用户是疑问就答疑问；要修再派工。

## 高发 Bug 模式（本会话实证，2026-08）

- **Element Plus date-picker 禁"今天"陷阱**：`:disabled-date="(d) => d < new Date()"` 带时分秒比较——今天 00:00 < 当前时刻，**今天被灰掉**，加急单"今天截稿/今天开稿"录不进。修法：归一化到当天 0 点再比（`(d) => d < startOfToday`）。审日期控件时见到裸 `new Date()` 比较就查。
- **create + postCreate 补写链路的跨字段校验缺口**：手动录单是"先 createOrder，再逐条补写 deadline/startDate/初始状态"。若 create 路径漏了跨字段校验（如 startDate ≤ deadline），而后端补写端点有校验（INVALID_START_DATE），会出现**订单已建、部分字段补写失败**的半成功态（弹"已创建但…失败"）。审任何"创建后多步补写"页时，逐字段对照**编辑页已有的 cross-validation**（如 OrderDetail 的 disableDeadlineDate/disableStartDateDate），缺了就补前端禁用 + 提交前兜底。
- **同功能两页文案不一致**：客户下单页参考图标签是"参考图（可选，最多5张，每张≤10MB）"，画师手动录单只有"参考图"三字、上限藏 tooltip。审 UI 文案时把同功能在客户端/画师端两侧的说法对一遍。
