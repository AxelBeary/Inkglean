# 视觉质量门禁（一号视角）：增量项目为什么变丑、门禁怎么堵

触发：视觉相关批次过审时；用户质疑页面观感时；派视觉批前。执行角色侧的截图/量化方法在独立技能 huiyue-visual-verification，本文件是一号门禁侧的纪律。

## 为什么顶级模型还出丑页面（2026-08-06 用户自我怀疑，判定入账）

一次性生成的项目好看 = 默认审美红利（训练数据里最流行的设计语言零成本获得）+ 无历史包袱（不用兼容 40 轮迭代的既有决策）+ 优化目标就是"看起来厉害"。
增量项目变丑 = 每批只看自己那一两个文件，**没有任何一步对"整页看起来如何"负责** + **视觉从未进验收门禁**（914+215 测试全测功能，一号审核只看 diff 不看截图）。

结论（对用户说的原话核心）：**模型能力从未是瓶颈，流程没调用它的审美才是。** 一次性生成与"维护演化 40 轮、多模板多配色、跑真实业务的系统"是两种能力，前者免费送，后者全世界都在交学费。

## 门禁纪律三条（2026-08-06 起，已入 STATUS 教训专节）

1. **视觉相关批次交付必附 before/after 截图，无截图不通过**——"实测优先批"的验收物是测量证据不是代码 diff（配套纪律见 references/third-party-report-triage.md 的"不实不许硬改"）
2. **定期派"只读全局巡检"角色**——全局观感只有一个人一次看全局才能发现（首例：四模板 × 亮暗 × 空态逐格截图体检批）；增量 diff 里永远长不出全局一致性
3. **设计规范存在 ≠ 执行纪律**：纸墨颜料盘设计系统用户认可过，但没人验渲染结果，照样漏——门禁必须验渲染截图，不只验 diff 合规

## A 测失败的根因复盘（2026-08-06 画师嫌弃太垃圾，追加最高优先级教训）

门禁三条仍不够——**它们管"批次过审"，没管"放人给真人看"这个动作**。A 测时后台本身半成品（topbar 刚被用户骂、吸底约稿条是坏的、体检清单 T1/T2/T3 挂着没修），用户说"开门"我就开了，画师第一眼印象就死了。

四个失败点（都要防）：
1. **A 测启动过早**：给真人看的版本必须自己先完整跑一遍核心旅程（画师后台：录单→接单→上传→交付；客户端：主页→下单→查单），每页截图，确认"像样了"才放人
2. **体检清单被"A 测为先"压下去**：四号体检报告早列出 T1/T2/T3，我判定挂起——结果画师看到的就是挂起状态。**"真实反馈优先于 AI 猜测"≠ 拒绝修复**，是排优先级；交互失效类（吸底条、死链）属于必须修的，不是可缓的
3. **把用户抱怨当噪声**：用户早说过"好多丑陋的页面"，我当成打磨期正常噪声——**用户对观感的不满 = 最高优先级生产事故信号**，界面是给画师做生意的门面，优先级高于功能打磨
4. **没有"上线前视觉验收"环节**：重建/上线动作没有把视觉门禁接进来

防再发：**任何"给真人看"的版本（A 测/上线/演示）前，一号必须亲自跑完整旅程截图验收；体检清单里的交互失效类（P1）不得以"等反馈"为由挂起；用户任何一句观感抱怨立即升级为门禁输入。**

## 用户自我怀疑时的回应姿态

不安慰不甩锅模型：诚实拆解两种能力的差别，把流程缺口认在自己（门禁侧）头上，给出已落盘的改正动作（截图门禁 + 只读巡检进流程）。实录：这套回应后用户接受（"ok。有道理"），教训同步入账 STATUS 专节防止回退。
