# 批量决策与具象化技巧（2026-08-02 REQ-014 桌面端对齐会话总结）

## 批量决策模式

当开放问题 ≥3 个且相互独立时，不逐条拷问，改为一次性呈现全部选项。

格式：
1. 每个问题给出 2~3 个方案档位（用 ★ 标注难度/工程量）
2. 每个方案附"我的建议"+ 一句话理由
3. 末尾汇总表：问题 | 选项 | 建议
4. 用户批量拍板，一次回复搞定多个

难度评估用非程序员能感知的语言（"一两周"vs"1~2个月"vs"比整个平台还大"），不用技术术语。

## 具象化：画场景

对抽象决策（数据迁移、冲突策略等），先画一个具体用户故事：
> "画师小林用了两年，攒了 87 条记录、12GB 文件。有一天她换了新电脑……"

然后从故事推导出设计约束，比纯抽象讨论高效 10 倍。

## 关键教训：先搜代码再回应

用户说"复用现有的XX"时，先搜代码确认现状再回应。本次会话中四号说"发码机制不存在"，实际项目已有 QQ 号+验证码登录设计（AUTH_DEV_MODE + BOT_WS_URL 预留）。用户纠正后四号才搜到。

规则：用户提到"现有的""我们已有的"→ 立即 search_files 验证 → 再回应。

## 需求文档落盘节奏

- 每轮讨论结束（用户说"好的""确定了""先写一下"）→ 立即更新文档 + commit + push
- 不攒批次。口头拍板即时落文档。
- 对齐记录按轮次追加（第一轮/第二轮/第三轮），不覆盖历史
- 已关闭问题表持续累积，开放问题表持续缩减
- 变更历史每轮加一行
