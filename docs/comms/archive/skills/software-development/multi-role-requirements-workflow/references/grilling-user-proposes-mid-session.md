# 拷问中用户中途提方案的处理模式

> 来源：2026-08-02 桌面伴侣应用需求对齐会话

## 场景

拷问过程中用户不等问完就自己抛出方案（"我建议像XX一样""加个XX按钮""等下，我觉得应该……"）。
用户可能同时表达不确定性（"逻辑好像挺难做的？""emmm 这个是不是很难？"）。

## 处理步骤（角色从"提问者"切换为"验证者+边界追问者"）

1. **先回答可行性**：用户问"难不难"时，先说难不难。如果不难，说出为什么（成熟模式、已有先例），给信心。不要跳过直接问下一个问题。
2. **命名模式**：把用户直觉翻译成已知模式（"这就是 Notion/Obsidian 的 local-first 模式"），降低不确定性。
3. **具象化确认**：把方案翻译成画面描述（"打开应用→左下角显示XX→点XX→变成XX"），问"这是你要的画面吗？"
4. **立刻追问边界**：方案里的模糊地带（切出账号后数据怎么办？冲突怎么处理？）趁热打铁。

## 关键纪律

- ⚠️ 不要无视用户插入的方案继续按自己的问题清单走。用户"等下"或"我建议"是最高优先级信号。
- 用户提方案时往往已经想了一半，你的价值是帮他补完另一半（边界、冲突、排除项），不是重新问"你要什么"。
- 如果用户方案确实难做，诚实说难在哪，给替代方案，不要为了配合而说"不难"。

## 实例

用户："等下，画师那边我建议像我们现在 dashboard 一样界面，但是多一个免登录使用按钮？免登录后左下角显示免登录相关的信息……emmm 逻辑好像挺难做的？"

正确处理：
1. "这个直觉很好，而且不难——Notion、Obsidian、Figma 桌面端都是这个路子：本地优先，登录是升级而不是门槛。"
2. 具象化：画出欢迎页两个入口 + 左下角两种状态的表格
3. 追问边界：切出账号后数据怎么办？免登录模式下能看到平台数据吗？
