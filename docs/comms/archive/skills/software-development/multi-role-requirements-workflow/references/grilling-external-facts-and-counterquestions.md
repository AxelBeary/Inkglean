# Grilling 第 0 步补充：外部事实核实与用户反问处理

> 配套 `grilling-step0-code-first.md`（代码摸底）。本文件补两块：外部事实怎么核实、用户反问怎么接。
> 来源：2026-08-05 深聊批实践（话题 1 QQ 机器人选型 / 话题 3 外链统一）。

## 1. 外部事实核实：搜索引擎被反爬挡时的替代路径

需求对齐经常要核实外部事实（开源选型、协议兼容性、第三方服务可用性）。Bing/浏览器搜索常被反爬挡住返回空结果，改用直查 API：

**GitHub API 查开源项目活跃度**（选型核实首选）：

```powershell
$repos = @('OrgA/Repo1','OrgB/Repo2')
foreach ($r in $repos) {
  try {
    $d = Invoke-RestMethod -Uri "https://api.github.com/repos/$r" -Headers @{'User-Agent'='hermes'} -TimeoutSec 20
    "{0} | archived={1} | pushed_at={2} | stars={3}" -f $d.full_name, $d.archived, $d.pushed_at, $d.stargazers_count
  } catch { "$r | ERROR: $($_.Exception.Message)" }
}
```

判断维度优先级：**archived（是否归档）> pushed_at（最近活跃度，看是否几天内有提交）> stars（社区规模）**。注意"未归档 ≠ 活跃"——go-cqhttp 式名义存活、实质停摆的项目要靠 pushed_at + 社区共识判断。

**无法实锤的项**（如需真机实测的兼容性）：需求稿里标注"待实测"并给出实测方法（例：腾讯身份验证器小程序能否扫第三方 TOTP 二维码 → 开发时生成测试码让用户扫一下即知），不阻塞定稿。

## 2. 用户反问 = 新侦查任务，不是讨论邀请

用户深聊中反问"有国产软件吗""两个输入区要不要统一"时：
- ❌ 不要凭记忆直接给方案清单
- ✅ 回去读代码/查事实核实，再给方案。例：问"两个输入区要不要统一"→ 先读 Settings.vue 确认两个输入区的字段结构、上限、客户端渲染方式，发现"一个功能两个入口"的冗余实锤后再提统一方案

## 3. 决策项呈现格式（用户偏好：一次全给）

核实完成后，把需要拍板的决策项**一次全呈现**（用户原话"你整个出来我一起看"），不要挤牙膏。每条格式：
- **问题一句话**（人话，不用技术术语）
- **我的建议 + 理由**（含工程量/成本对比）
- **备选方案的代价**（诚实说，不藏缺点）

决策项控制在每轮 3 个左右，答完立即落稿，不攒批。

## 4. 决策变更传播清单（拍板后立即执行）

用户拍板改变既有方向时（如"QQ 发码登录改 TOTP"），落稿同时搜索全部引用该方向的文档并同步：
- `rg -l "关键词" docs` 列出波及面（排除 archive/）
- 我有权限的（STATUS 待办池、REQ 文档）→ 当场改
- 我没权限的（技术文档 CONTEXT.md/切换指南）→ 需求稿"传播影响"章节列出，转交时点名
- 代码里的 TODO 注释 → 标注"由实施角色处置"，四号不碰代码
