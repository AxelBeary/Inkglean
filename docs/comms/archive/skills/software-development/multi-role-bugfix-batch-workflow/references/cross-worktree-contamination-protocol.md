# 跨角色 worktree 污染协议（2026-08-04 收款三连实证，一号拍板）

## 场景

在自己 worktree 里发现**你没碰过的陌生改动文件**——通常是另一角色的半成品改动漏进来。

收款三连实例：五号 worktree（基于 cddb3f2）里突然出现 order.routes.ts 改动，内含三号 B1 的 enrichOrderForArtist 调用但函数定义缺失 → 32 个测试 500。五号一度开始侦查"谁写进来的"，被一号打断：**停止侦查，根因已实锤，照恢复步骤做**。

## 协议步骤

1. **不要并入你的提交**，也不要深挖别人 worktree 的来龙去脉——直接报告一号，等一号定性。
2. **保全证据再还原**：
   ```powershell
   git diff <file> | Out-File -Encoding utf8 <workspace>/temp/orphan-<file>.patch
   git checkout -- <file>   # 只还原这一个文件，你授权内的改动全保留
   ```
3. **典型根因**：你的分支基于旧 master，另一角色的改动被部分带进你的文件（调用在、定义丢），导致"调用未定义函数 → 500"的一批测试失败——**与你的本批工作无关**，别背锅也别顺着往下查。
4. **一号确认后的标准恢复**：`git merge master` 拉入完整版 → 重跑 server/web 全量测试重建基线 → 继续本批任务。

## 辅助判断："这堆失败是不是我改出来的"

`git stash` 掉自己的改动再跑同一批失败文件——仍失败 = 存量/他人改动，与己无关。stash 完记得 `git stash pop`。

## 教训

- 开工时 `git status --short` 干净 ≠ 收工时干净：并行角色会话可能误写共享路径。commit 前逐文件核对 `git status`，陌生文件一律走本协议。
- 报告时给一号三要素：脏文件路径、diff 摘要（调用在/定义丢之类）、自己的改动清单完好——一号才能快速定性。
