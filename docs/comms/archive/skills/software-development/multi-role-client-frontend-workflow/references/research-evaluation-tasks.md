# 只出方案不实施（Research/Evaluation）任务工作流

一号有时派"评估/预研"任务（分支名 `research/*`，授权"只读，不改代码"）。这类任务的交付物是 comms 方案文件，不是代码——但**同样必须 commit 进 git**（未进 git = 未交付）。

## 执行步骤

1. **读派工文件，逐条列出要求回答的问题**。方案必须按一号提问的顺序逐条回答，不遗漏、不自行扩展问题。
2. **确认 worktree + 分支**：`git branch --show-current` 确认在 `research/*` 分支上。
3. **读全链路再出方案**（这是评估质量的关键）：
   - 前端视图文件（目标组件的 template + script + style 全读，不只看派工指出的行号范围）
   - SPEC 文档（找到"未来扩展"段落，确认预留了什么）
   - **后端路由 + service 层**：确认 API 是否已存在、参数格式、校验规则（如日期格式要求）。常见发现：API 已就绪 → 方案中"不需要后端改动"，工时大幅缩短
   - **前端 API 封装层**（`web/src/api/index.js`）：确认是否已封装。已封装 = 纯前端增量
   - **代码库内已有交互先例**：如项目已有 Pointer Events 拖拽（滑块取消的 `setPointerCapture` 模式），则"原生实现不引库"有实证支撑，不是空口建议
4. **写 comms**：`02-to-01-{主题}-research-{日期}.md`，结构见下。
5. **commit**：`docs(client): {主题}设计评估（核心结论摘要）`。
6. **转交**：输出"二号转交一号，文件：docs/comms/xxx.md" + 要点表格（每条问题一行结论）。

## comms 方案文件结构

```markdown
# 二号 → 一号：{主题}设计评估
> 日期 / 分支 / 性质：设计方案，不含实施

## 现状摘要
（目标组件现有结构、坐标/数据模型、已就绪的后端+前端 API——带行号和函数名）

## Q1~Qn：逐条回答一号的问题
（每条用评估表格：方案 | 评估，然后给结论 + 理由。
  交互类问题要覆盖：操作模型、吸附/精度、视觉反馈、校验防呆、提交方式）

## 改动量估算
（表格：文件 | 改动 | 行数，加总行数 + 工时。
  明确写出"不需要后端改动/不需要新依赖/不需要改共享组件"——一号排期最需要这些否定句）

## 风险与边界
（表格：风险 | 应对。把"本次不做"的边界写清楚）

## 建议实施节奏
（v1 做什么 / v2 做什么 / 不做什么——给一号排期用）
```

## 易错点

- **只看派工指出的行号范围**：派工说"L322-385 附近"，但拖拽方案需要知道坐标换算函数、数据源、样式类——必须读完整文件。
- **假设 API 不存在**：先查 `api/index.js` 和后端 routes。本项目多次出现"前端已封装、后端已有"的情况，漏查会虚报工时。
- **方案文件不 commit**：research 分支只改 docs/，但一样要 commit。一号审核只读 git diff。
- **回答超出派工范围**：只回答一号问的问题。"月历要不要也做"如果一号问了就答（答"不做+理由"也是答案），没问 don't 自行扩展。
