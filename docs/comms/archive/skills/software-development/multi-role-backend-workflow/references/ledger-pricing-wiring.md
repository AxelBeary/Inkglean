# 账本式计价引擎接线踩坑集（REQ-025 第二阶段实战，2026-08-05）

给既有订单系统接入"条目账本 + 锁价分摊 + 守恒断言"类计价引擎时反复验证过的模式与陷阱。适用于任何 append-only ledger + conservation assertion 的服务层接线。

## 1. 双重记账（最严重，测试前靠推演抓到）

**症状**：全锁订单改价后 Σ条目 ≠ final_price，守恒 A1 必挂。
**根因**：调用方先写原因条目（manual_adjust/extra_item），分摊函数发现全锁又写 extra_charge/refund 条目——同一笔 delta 记了两次。
**修法**：条目落账**统一收口到分摊函数**（如 applyDeltaToInstallments），按 delta 去向决定条目类型：摊进未锁节点→写原因条目；全锁→写 extra_charge_after_close/extra_refund_after_close（不再写原因条目）。调用方一律不直接写条目。
**自检**：任何"写条目+调分摊"相邻两行代码都要问：这两步会不会对同一 delta 各记一笔？

## 2. 懒回填必须在变更之前（ensureBaseEntry 时序）

存量订单无账本时按当前价补 base 条目。**必须在 UPDATE final_price / adjustFinalPrice 之前调用**，否则补录的 base 取到新价，Σ条目直接错。所有"读当前状态补录"的辅助函数都适用此规则：先补录，后变更。

## 3. 守恒断言要有配置守卫（Σbp=100%）

"总价 = Σ节点价"只在比例和=100% 时方程有解。Σbp≠100% 的订单（人工数据/历史残留）Σ节点价恒小于总价，断言无解。挂载点加 `if (bpSum !== 10000) return` 守卫。教训：守恒断言只挂载在"不变量有定义"的配置域上，否则人工测试数据会误触发自检抛错。

## 4. 派生记录用当前有效价，不用历史价

generateInstallmentsForOrder 原用 total_price_cents 建节点；缓冲期改过价的订单 final≠total，递补时守恒必挂。改用价格回退链（final→total→snapshot×100）。规则：从父记录派生子记录（分期/快照）时，金额一律取"当前有效价"回退链，不取建单时原值。

## 5. 退役旧函数时测试适配三件事

- 直接调用被删函数的测试 → 改走新入口（如 recalc→generateInstallmentsForOrder/addExtraItem）。
- 断言旧语义数值的测试 → 按新语义重算预期值（如"已付清节点改价后涨价"→新语义锁定不涨）。
- 数账：基线数 + 新增数 = 全量数，逐个对得上才算零回归。

## 6. 测试文件位置陷阱

vitest.config include 只扫 `tests/**/*.test.js`——引擎测试放 `src/**` 不会被跑；TS 引擎模块在 JS 测试里用 `.js` 后缀导入（vite 解析到 .ts）。

## 7. 测试数据隔离

同一测试文件多个用例 seed 画师时 QQ 号/subdomain 必须唯一（artists.qq_number UNIQUE），用 orderNo 派生 QQ（如 `'799' + orderNo.slice(-3)`），不要固定值。

## 8. 工作目录陷阱（PowerShell，高频复发）

在 server/ 子目录跑完测试后 `Set-Location ..` 会跳出 git 仓库（"fatal: not a git repository"）。**每次 git 命令前都用绝对路径 `Set-Location '<worktree根>'`，永远不用相对导航**——连续两个会话累计踩了 6 次，每次都是 commit 时报错才发现。跑测试可以 cd 进 server/，但 git 操作前必须显式回根。

## 9. 纯函数预期值要手算复核

测试里自己写的预期值也会算错（曾把尾款已收 13000 写成 7000）。写断言前对每个数字做一次独立推演，特别是"尾款吸收剩余/尾差"类计算。

## 10. 超付处理：压尾款待收变负，不与额外应收冲抵

守恒 A2（总价−已收 = Σ待收 + 额外应收 − 额外应退）中，已收超出 Σ节点价的纯超付**全额压到尾款待收变负**，不要设计"超付先冲抵额外应收"逻辑——数学上 A1/A2 同解（Σ待收 ≡ Σ节点价 − 已收），冲抵反而破坏方程。自检：任何"两笔应收互相抵扣"的推导先写恒等式验证。

## 11. 共享实体类型缺后加列：局部结构断言，不动类型文件

entities.ts 的 Order 接口没收录后加的 final_price_cents 列（不在授权清单）。修法：调用点 `as (Order & { final_price_cents: number | null })` 局部断言，不修共享类型文件——最小变更纪律优先于类型完备性。

## 12. 实现被前批"有意暂缓"的功能时，先 grep 占位测试

done 无痕改价守卫是五号先行批有意不拦的（测试注释写着"待 REQ-025 第二阶段负条目机制一起上"）。本批实现该机制时必须同步更新占位测试（TC-PG-03 从 200 改 400）。开工时 grep 派工关键词 + "待第X阶段/暂缓/占位"注释，把前批预留的测试一并更新，否则全量测试会红。

## 13. 派生"已收/已分配"状态：从权威聚合列顺序填充，不读残留列

节点级 paidCents 一律从 orders.paid_total_cents 顺序填充推导（每节点至多填满），不读 installments.paid_cents 旧残留列。规则：当存在"权威聚合列 + 派生明细列"且明细列可能 stale 时，读路径只信聚合列，明细列仅写不读。

## 14. 交付报告附端到端数值推演表

守恒类功能的交付报告放一张"步骤 × 操作 × 节点价 × locked × 守恒"表（真实测试用例数值），让审核者不用跑测试就能核对关键承诺（如"已收节点价不再变"）。比纯文字描述可信度高一个量级。
