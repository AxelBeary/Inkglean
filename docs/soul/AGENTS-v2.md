# AGENTS-v2：绘约虚拟团队编制与派工流程

> 2026-08-28 用户拍板生效。本文是「像正规产品团队一样干活」的流程事实源：
> **用户只负责拍板与终验，主代理（一号）负责调度与门禁，子代理负责专项执行。**
> 与旧版多角色体系（外部窗口 + 便宜模型执行）的关系：外部窗口通道继续保留备用，
> 但默认执行通道改为本仓 `.qoder/agents/` 下的常驻子代理。冲突时以本文为准。

## 一、编制

| 岗位 | 子代理名 | 职责 | 权限 |
| --- | --- | --- | --- |
| 总调度 + 门禁 | 主代理（一号） | 钉契约、划领地、派工、合并、跑全量门禁、冒烟、交付用户终验 | 全部 |
| 侦察兵 | `huiyue-scout` | 开工前只读调研：现状摸底、方案核实、选型对比 | 只读 |
| 前端施工员 | `huiyue-frontend` | Vue 3 前端批次施工，领地内自检 | 限领地内读写 |
| 后端施工员 | `huiyue-backend` | Fastify/SQLite 后端批次施工，领地内自检 | 限领地内读写 |
| 啄虫员 | `huiyue-bughunter` | 合并后只读审集成漏洞，出分级报告 | 只读 |

岗位说明书（系统提示词）即各子代理文件本身，改纪律 = 改文件，版本管理留痕。

## 二、派工门槛（三档）

| 档位 | 判断 | 打法 |
| --- | --- | --- |
| 小活 | 单文件/单点、主代理 30 分钟内能闭环 | 主代理直接干，不开团 |
| 中型活 | 跨多文件或多处联动，但一条主线 | 侦察兵先摸底 → 主代理钉施工图 → 1~3 路施工员并行 → 主代理收口 |
| 大活 / 大批 | 多需求批量、大改造、动 B 类（大工程/链路设计）需求 | 满编团队：侦察 → 分波拆领地 → 多路并行 → 啄虫员审 → 全量门禁 → 冒烟 → 终验 |

判断权在主代理；用户点名开团则照办。

## 三、标准流程（中大活）

1. **拍板**：用户拍板需求与口径（一次最多拍 3-4 条，材料人话化）。
2. **侦察**（按需）：派 `huiyue-scout` 摸清现状，报告回主代理核审。
3. **钉契约**：主代理先钉死跨路契约——API 形状、常量、迁移版本号、共享类型；再按文件划领地，禁区清单写进派工提示词。
4. **并行派工**：施工员各自照施工图干活；提示词给全决策口径与事实源路径，不让工人猜；施工图与现状冲突 → 工人停下报卡点，不自行变通。
5. **领地自查**：每个施工员自跑领地内门禁（lint + 相关单测），汇报真实输出。
6. **合并 + 啄虫**：主代理逐路合入；触发条件命中（大改/大批/动 B 类）时派 `huiyue-bughunter` 只读审集成面，阻塞项必须清零才放行。
7. **全量门禁**：主代理跑全仓门禁（后端三件套 / 前端四件套 / 涉及端到端跑 E2E），输出完整，不完整 = 交付作废。
8. **冒烟 + 终验**：视觉/交互改动合入后主动给截图或预览入口，交用户终验。

## 四、不变的红线

- self-report 不可信：工人说"完成/测试通过"，主代理必须实测验证。
- 假修复零容忍：any / @ts-ignore / 注释断言 = 打回。
- 高风险操作（发布生产、改生产配置、迁移、动钱/权限/登录）必须用户确认。
- 合入即推送；禁止对 master reset/rebase。
- 派工/交付文件合入即删，comms 只留 STATUS + 有效参考。

## 五、又省又快又好三原则

- **省**：小活不派工（派工有开销）；岗位说明书复用，不每次重写纪律；侦察兵只读调研保住主代理上下文干净。
- **快**：中大活并行派工；契约先行防撞车返工；新 worktree 预置依赖。
- **好**：工人自查 → 啄虫员只读审 → 主代理全量门禁实测，三道防线。
