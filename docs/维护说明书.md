### 变体：宿主机已有反代 / 套 Cloudflare（v1.0.0-beta.2 首台公网服务器实战总结）

默认一键安装假设「容器 Caddy 是唯一入口」。若服务器上已有宿主机 Caddy/Nginx，或域名要走 Cloudflare 代理，按本节改。

#### ① 新建 docker-compose.override.yml（2026-08-23 事故后定稿，勿改 docker-compose.yml）

> ⚠️ **不要直接改 `docker-compose.yml`**：它是 git 跟踪文件，手工删 caddy 段的旧改法会在一次 `git reset --hard`（或换机克隆）后被仓库原版覆盖复位——容器 Caddy 随之复活抢 80/443（报 `address already in use`），web 的 3000 回环映射同时丢失，系统 Caddy 敲 127.0.0.1:3000 落空 → 全站 502（2026-08-23 cute-goose-1 事故即此链，复盘见 OPS.md §13）。

在项目目录**新建**这张配置单（文件名必须叫 `docker-compose.override.yml`；它不进 git，`git pull` / `reset --hard` 都碰不到它）：

```yaml
# docker-compose.override.yml —— 外部反代机器专用
services:
  web:
    ports:
      - "127.0.0.1:3000:3000"   # 只绑回环，防外网绕过反代直连
  caddy:
    profiles:
      - "disabled"              # 永不起用容器版 Caddy，80/443 让给宿主机 Caddy
```

`docker compose up` 会自动合并这张单（update.sh 照常可用），无需再动 `docker-compose.yml` 一行。若容器版 Caddy 已被误起过，`docker rm -f commission-caddy` 清掉僵尸即可（profile 禁用后不会再创建）。

#### ② 宿主机 Caddy 站点块（两条都不能省）

```
你的域名 {
    encode zstd gzip
    request_body {
        max_size 55MB        # 必须！Caddy 默认 10MB，会截断 50MB 交付文件上传（413）
    }
    reverse_proxy 127.0.0.1:3000
}
```

改完 `caddy validate --config /etc/caddy/Caddyfile && systemctl reload caddy`。

> 不套 Cloudflare 的直连部署用上面这份即可。套 CF 橙色云的看 ③，reverse_proxy 要多一行真实 IP 透传。

#### ③ 域名套 Cloudflare（橙色云）时证书怎么签

Let's Encrypt 会被 Cloudflare 挡住签不下来（现象：本机 curl https 报 TLS internal error / 浏览器重定向循环）。标准解法：

1. Cloudflare 后台 → SSL/TLS → 模式选 **Full (Strict)**
2. SSL/TLS → Origin Server → **Create Certificate** 生成源站证书（有效期 15 年，域名列表含你的子域名）
3. 证书/私钥存到服务器（如 `/etc/caddy/certs/域名.crt|.key`；Caddy 进程非 root 运行，私钥需让它读得到：`chown root:caddy` + `chmod 640`，root 独享 600 会报 permission denied 致 reload 失败）
4. 站点块改用显式证书，**并加一行真实 IP 透传**（后端限流才能按用户计，否则全站共享 CF 边缘节点配额，正常用户会被误伤 429）：
```
https://你的域名 {
    tls /etc/caddy/certs/你的域名.crt /etc/caddy/certs/你的域名.key
    encode zstd gzip
    request_body {
        max_size 55MB
    }
    reverse_proxy 127.0.0.1:3000 {
        header_up X-Forwarded-For {http.request.header.CF-Connecting-IP}
    }
}
```
`header_up` 那行的作用：把 CF 写好的用户真实 IP（CF-Connecting-IP）作为唯一 X-Forwarded-For 传给后端；后端现有信任配置（只信内网代理）会自动采纳它。不经 CF 直连时该头为空被删，后端回退用连接地址，行为仍真实。
附带安全收益：源站证书只有 Cloudflare 认，攻击者即使拿到真实 IP 直连，浏览器也会报证书不受信任。进阶加固（推荐）：
- **开启 Cloudflare Authenticated Origin Pulls**（SSL/TLS → Origin Server 页开关）：CF 回源时出示客户端证书，源站只认 CF 的加密连接——防源站 IP 泄露后攻击者绕 CF 直连伪造 CF-Connecting-IP 绕过限流；Caddy 端需配套验证客户端证书（完整配置、生效顺序与实战坑见 OPS.md §12.2）。
- 或防火墙 80/443 只放行 Cloudflare IP 段（https://www.cloudflare.com/ips/）——前提是该端口无其他需直连的服务。

#### ④ 常见卡点速查

| 现象 | 原因与解法 |
|---|---|
| 容器反复重启，日志 SQLITE_CANTOPEN | root 建的 data/uploads 目录容器内普通用户写不进：`chown -R 1000:1000 data uploads` 后重启（新版安装脚本已自动处理） |
| 服务起不来，日志提 SESSION_SECRET | 密钥为空或过短：`openssl rand -hex 32` 生成填入 .env 重启 |
| 安装失败后不知道口令在哪 | 口令在 .env：`grep SETUP_TOKEN .env`，或 `docker compose exec web printenv SETUP_TOKEN` |
| 开箱向导不预填 QQ 号 | 设计如此（配置敏感值不回显网页）：手动填与 .env ADMIN_QQ 一致的 QQ 号即可；两边不一致不会报错，但建议一致（数据库重置恢复时以 .env 为准） |
| 浏览器重定向循环 | 橙色云 + SSL 模式还是 Flexible：改 Full (Strict)；或双 Caddy 抢端口（见①） |
| 服务器本机 `curl -sk https://127.0.0.1/` 状态码 000 | AOP 开启后的预期行为：防盗门在 TLS 层只认 Cloudflare 客户端证书，本机裸敲没证书被直接拒，别当故障。服务器内自检走 `curl -s http://127.0.0.1:3000/api/health`，全链路验收走浏览器 |

### 一键更新（Linux 服务器，首选）

服务器以 git 部署（git clone 出来的项目目录）时，直接用仓库自带脚本，它是版本更新的**首选方式**——一条命令自动完成：

1. 更新前 DB 备份（`VACUUM INTO` 一致性快照，不停服安全，保留最近 2 份轮转）
2. `git pull --ff-only` 拉取代码（有本地改动时会拒绝合并并停下）
3. 写 `data/version.json` 版本标记（自检页「系统更新」面板据此对比）
4. `docker compose up -d --build` 重建容器
5. 等待 healthy（最多 150s）
6. 体检（健康接口 + 数据库迁移版本，当前 v74；最新以 migrations/index.ts 末尾为准）
7. 汇报结果并给出回滚命令

任一步失败即停，并给出对应的回滚命令。

```bash
cd /项目目录
bash scripts/update.sh
```

> 前提：服务器项目目录是 git 仓库（2026-08-18 起新部署均为 git clone；早期 ZIP 安装包部署的需先迁移为 git 仓库）+ Docker 可用。

### 启用每日备份（Linux 服务器）

仓库自带 `scripts/server-backup.sh`：数据库 VACUUM INTO 快照（留 7 份）+ uploads 打包（留 2 份），失败写入日志。用 crontab 挂上每天自动跑：

> ⚠️ **产物仅供人工取用，恢复须手工指路（F-16）**：本脚本产物命名为 `commission.db.bak-daily-<YYYYmmdd-HHMMSS>`，与恢复端（`restore-db.ts` / `verify-backup.mjs`）只认的官方 ISO 命名 `commission.db.bak-<时间戳>` **不匹配**——恢复时会被无声忽略（目录里若还留着官方命名的旧档，就会"明明有昨天的备份、恢复出来却是旧档"）。Linux 每日备份优先改用官方脚本 `node server/scripts/backup-db.ts`（产物即恢复端认得，且与 Windows 侧 `daily-backup.bat` 同源、支持三档轮转）。`server-backup.sh` 本体转调官方脚本的重做属独立施工（本批不动脚本，见 ledger）。

```bash
crontab -e
# 加入这行（每天 03:30，路径换成实际项目目录）：
# 30 3 * * * /root/inkglean-git/scripts/server-backup.sh >> /root/inkglean-git/data/backups/cron.log 2>&1
```

验证：`crontab -l` 看到该行；手动跑一次 `bash scripts/server-backup.sh` 应输出两行 OK。

## 五、域名与 HTTPS

### DNS 解析（路径访问模式）
当前画师主页走路径 `https://你的域名/artist/主页标识`，只需一条 A 记录，**无需泛解析**：
```
类型: A
主机记录: @（或留空）
记录值: 你的服务器IP
```

### Caddy 自动 HTTPS
Caddy 默认自动申请 Let's Encrypt 证书，无需手动配置。

如果使用 Cloudflare 代理（橙色云朵），需要：
1. 安装 Caddy 的 cloudflare DNS 插件
2. 在 Caddyfile 中配置 `acme_dns cloudflare <API_TOKEN>`
3. 或者将 Cloudflare SSL 模式设为 "Full (Strict)"

### 添加新画师
不需要任何 DNS 或 Caddy 配置变更！
只需在管理员后台"添加画师"并填写主页标识即可，画师主页通过 `https://你的域名/artist/主页标识` 访问。

> **Phase 2 规划**：未来将支持泛子域名（`alice.你的域名`），届时需配置泛解析 DNS 和 DNS-01 证书。

## 六、环境变量说明

| 变量 | 说明 | 默认值 | 生产必改？ |
|------|------|--------|-----------|
| DOMAIN | 主域名 | 无默认值（Caddyfile 的 `{$DOMAIN}` 必须由 .env 提供） | ✅ 必须 |
| PORT | 服务端口 | 3000 | ❌ |
| UPLOAD_DIR | 上传文件路径 | ./uploads | ❌（Docker 内已设为 /app/uploads） |
| DB_PATH | 数据库路径 | ./data/commission.db | ❌ |
| ADMIN_QQ | 管理员QQ号 | 无（判定顺序见下注） | 按需 |
| SESSION_SECRET | 会话签名密钥（同时用于文件签名 URL HMAC） | ⚠️ 生产环境必须设置，否则启动报错 | ✅ 必须改！ |
| ~~SIGN_SECRET~~ | ~~虚构变量~~（文件签名 URL 实际用 SESSION_SECRET） | — | 不配置 |
| COOKIE_SECRET | httpOnly cookie 签名密钥 | 回退到 SESSION_SECRET | ✅ 建议单独设置 |
| TRUST_PROXY | 信任的代理 IP 段 | 172.16.0.0/12,10.0.0.0/8,192.168.0.0/16 | 按需 |
| TZ | 容器时区 | UTC | ✅ 建议 Asia/Shanghai |
| CORS_ORIGIN | 生产环境CORS来源 | 空（禁止跨域） | 按需 |
| AUTH_DEV_MODE | 开发模式 TOTP 绑定接口附密钥明文 `_dev_secret` | false | ✅ 生产必须关闭 |
| SENTRY_DSN_BACKEND | Sentry 错误监控后端 DSN | 空（禁用） | 按需 |

> **ADMIN_QQ 判定顺序**：`platform_config.admin_qq`（数据库）非空时优先，为空才回退环境变量 `ADMIN_QQ`（`server/src/shared/middleware/auth.ts`）；首次安装由 `/setup` 向导写入该键，`npm run db:seed` 未设 `ADMIN_QQ` 时使用 `10003`（仅种子数据，不是环境变量默认值）。

### NODE_ENV 与 AUTH_DEV_MODE（TOTP 时代，REQ-027）
```bash

```

### TOTP 动态口令：手机丢失 / 换设备自助重绑（REQ-027）

画师或管理员的手机丢失、验证器 App 删除、换手机后，动态口令登录会失败。两条解决路径：

**路径一：管理员在后台重置（画师丢失时用）**

管理员登录后台 → 画师管理 → 找到该画师 → 点「重绑」→ 生成二维码给画师扫 → 画师报出 App 上的 6 位码 → 管理员输入确认。

**路径二：服务器本机 CLI 自助重绑（管理员自己丢失 / 新部署未绑定时用）**

后台重置入口本身要先登录，管理员丢手机会形成死锁——唯一出路是服务器本机操作：

```bash
cd server
npm run totp:rebind -- <QQ号>
# 例：npm run totp:rebind -- 10003
```

脚本一次完成三件事：① 生成新密钥直接入库并标记已绑定（**旧密钥立即失效**）；② 生成二维码（`temp/totp-rebind-<QQ号>.png`），用验证器 App 扫码（扫不了可用控制台打印的密钥手动录入）；③ 自动现算动态码打真实登录接口做端到端验证。之后用 QQ 号 + App 新码登录即可。

Docker 部署时也可在容器内执行（DB 路径自动解析为容器挂载的 `/app/data/commission.db`）：

```bash
docker compose exec -T web npm --prefix /app/server run totp:rebind -- <QQ号>
```

> ⚠️ 安全边界：该命令只有能物理操作服务器的人可执行（不经网络、不开端口）。执行后旧验证器 App 上的动态码全部作废。
> DB 不在默认位置时可用环境变量覆盖：`DB_PATH=/路径/commission.db npm run totp:rebind -- <QQ号>`

### 速率限制（v0.5 新增）
所有公开接口均有内存桶速率限制（按 IP + 端点独立计数，阈值以代码 `guardRateLimit(...)` 调用为准）：
- TOTP 登录 verify：10次/5分钟（另有账号级防爆破：连续错误 5 次锁定 15 分钟）
- 公开下单：10次/10分钟
- 订单进度查询：20次/5分钟
- 客户留言：2次/分钟

触发限制返回 HTTP 429。限制器在进程重启后重置（无需清理）。
如需调整阈值，修改各 routes 文件中的 `guardRateLimit(...)` 调用（如 `auth.routes.ts`）。

> 📖 开发→生产切换的完整步骤见 [开发→生产切换指南](开发→生产切换指南.md)
