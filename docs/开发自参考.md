## 技术栈
- 前端：Vue 3 + Element Plus + Pinia + vuedraggable + **vue-i18n@11**（中英双语）
- 后端：Node.js（支持 22~26）+ Fastify 5
- 数据库：SQLite (better-sqlite3, WAL 模式)
  - **部署边界（清扫批 2026-08-05 明确）**：better-sqlite3 是单进程单连接同步模型——同一 DB 文件**不支持多实例并发共享**（多副本部署需外置 DB 如 PG/MySQL）；写操作天然串行。当前单实例量级（画师运营 + 订单平台，QPS 远低于 SQLite 单机上限 ~10 万写/秒）完全够用，属**预期架构边界而非缺陷**；若未来多实例/高并发需求出现，再评估迁移，勿在边界内引入 Redis 等复杂度。
- 文件存储：本地磁盘 uploads/
- 反向代理：Caddy（自动 HTTPS，路径访问 /artist/:subdomain，C48 已定不做子域名）
- 部署：Docker Compose
- 测试：Vitest + Playwright E2E（用例数以实测为准；**基线数字随批次变动，以 docs/comms/STATUS.md 最新条目为准**）
- 语言与类型门禁：全仓已于 2026-08-19 完成 TypeScript strict 一次性收尾（STATUS v132，取代早期增量迁移思路）——server src/tests/scripts、web src（含 136 个 vue `script lang="ts"`）与配置文件（vite.config.ts/vitest.config.ts/eslint.config.ts/scripts/*.ts）、e2e 全 TS；仓库无 `.js` 源码残留（保留 install.mjs、scripts/*.mjs/.ps1/.sh 及 docs/soul 内脚本），web tsconfig `allowJs` 已关闭。类型门禁：server `npm run typecheck` = 主 tsconfig + tsconfig.scripts.json + tsconfig.tests.json（tests 全量 strict）；web `npm run typecheck` = vue-tsc + tsconfig.scripts.json；根 `npm run typecheck:e2e` = e2e/tsconfig.json。web devDeps 新增 tsx/jiti/@types/node，根 devDeps 新增 tsx/@types/node/typescript(~5.9)；`eslint.config.ts` 加载依赖 jiti。**新增代码一律 .ts/lang="ts"**

## 核心设计决策

### 1. Feature-based 目录（v0.2 重构）
- 每个业务域一个目录：`features/{auth,artist,order,upload,admin,pricing,guestbook}/`
- 每个 feature 包含 `*.service.ts`（业务逻辑）+ `*.routes.ts`（HTTP 路由）
- 跨 feature 共用的放 `shared/`（validate、errors、middleware）
- `app.ts` 是应用工厂，`index.ts` 只负责启动

### 2. 拖拽排序逻辑（重要！）
- 拖拽即绝对顺序，`priority` 仅作展示标签不影响排列
- 实现在 `features/order/order-queue.service.ts` 的 `reorderQueue(artistId, orderedIds)`（v0.16 拆分后）
- 前端传入完整的排序后 ID 数组，后端按序分配 `queue_position`
- 前端用 vuedraggable，`@end` 事件触发后端重排

### 3. 双模式（自助 + 手动）
- 客户可以自助填表下单（source='self'）
- 画师可以手动录入（source='manual'）
- 两种进同一个队列，管理方式一致
- 画师可以把状态改为"排满/休息"来关闭自助下单

### 4. 认证方案（REQ-027 TOTP 动态口令）
- **登录 = QQ号 + TOTP 动态码**（RFC 6238，30 秒步长 6 位数字，验证器 App 扫码绑定），旧登录码机制已移除（迁移 v41 DROP login_codes 表）
- 防爆破：连续错误 **5 次**锁定 15 分钟（`TOTP_MAX_ATTEMPTS` / `TOTP_LOCK_DURATION_MS`，auth.service.ts）
- 开发模式：`AUTH_DEV_MODE=true` 时 TOTP 绑定接口（bind-init）响应附带密钥明文 `_dev_secret`（生产必须 false）
- 会话 Token：HMAC-SHA256 签名，`base64url(JSON{id,t}).base64url(sig)`，7天有效
- **v0.5**：生产环境未设置 `SESSION_SECRET` 时启动报错（不再静默回退）
- **v0.6.2**：开发模式辅助功能通过 `AUTH_DEV_MODE=true` 环境变量显式开启（不再依赖 NODE_ENV）
- 无密码设计
- 管理员 QQ 通过 `ADMIN_QQ` 环境变量首次引导，运行时从 `platform_config` 表读取（支持运行时更换）；管理员 TOTP 绑定失败/手机丢失 → 服务器本机 `npm run totp:rebind -- <QQ号>` 自助重绑

### 5. 画师主页路由方案
- **当前实现（v0.4.1+）**：前端使用参数化路由 `/artist/:subdomain`，后端 `GET /api/artists/:subdomain` 识别画师
- **Phase 2（未实现）**：泛子域名（`alice.example.com`），需泛解析 DNS + DNS-01 证书 + 前端 hostname 路由映射
- 开发环境直接使用 `/artist/alice` 路径访问
- 管理员后台添加画师时填写 subdomain 字段即可，无需 DNS 变更

### 6. 文件上传

### 8. 订单号生成（v0.5 重构）
- 格式：`{身份码}-{序号}`，如 `ALICE-001`
- 身份码（artist_code）：2-20位大写字母/数字，画师可自定义，默认子域名大写（823 规则对齐批：上限 10→20，主页标识同步去连字符，两规则同构）

## 已知注意事项
1. `server/src/app.ts` 中 pino-pretty 是 dev 依赖，生产环境自动跳过（动态 import + try/catch）
2. 客户端路由使用 `/artist/:subdomain` 参数化路径（v0.4.1 起），不再使用 `?artist=` 查询参数
3. **后端 API 统一返回 camelCase**（`orderNo`、`artistName`、`tierName`、`weiboUrl`），前端模板必须匹配，不要用 snake_case
4. Docker 多阶段构建：前端在 `frontend-build` 阶段编译，生产镜像只含 `--omit=dev` 后端依赖
5. 测试中 `auth.service.ts` 的 SECRET 在模块加载时固定，vitest.config.ts 的 env 必须在 import 前生效
6. `entrypoint.sh` 先 `npx tsx scripts/check-db.ts` 预检（失败走 `restore-db.ts` 修复），再 `npx tsx src/index.ts` 启动服务，不依赖 CWD
7. `db/init.ts` import 时无副作用，CLI 执行或 `tests/setup.ts` 显式调用 `initDatabase(db)` 才建表
8. 所有路由层不含裸 SQL，业务查询统一在 `*.service.ts` 中
9. `upload.routes.ts` 的 `UPLOAD_DIR` 由 `app.ts` 通过插件选项传入，保证与静态服务路径一致
10. i18n 语言包键名按页面命名空间组织，`common.*` 为跨页面共享（状态/优先级/按钮）
11. 暗色主题依赖 `html.dark` 类名，Element Plus 组件自动适配；自定义样式必须用 CSS 变量
12. **客户端 API 分层**：公开数据用 `artistPublicApi`（getAll/getProfile），订单用 `orderApi`（create/track/delivery），画师后台用 `artistApi`（需 token）。切勿混用
13. 后端 `GET /api/artists/:subdomain` 一次返回 profile+tiers+artworks+rules，前端不需要分多次请求
14. 后端 `deliverables` 数组中 `url` 字段已含 `/uploads/` 前缀，前端 `openFile()` 直接 `window.open(url)` 即可
15. **v0.5**：`requireAuth` 中间件注入 `req.artist` 完整对象（含 id/qq_number/name/artist_code），路由层用 `req.artist.id` 做归属校验
